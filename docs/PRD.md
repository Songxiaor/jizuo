## 1. 一句话定位

LinkDigest 是一款 macOS 原生、local-first 的链接理解工具：用户在 Chromium 浏览器中主动发送当前页面，Mac APP 保存可核查的原文，并使用用户自己的模型连接完成总结、翻译和导出。

## 2. 第一版为什么存在

### 2.1 首要用户

第一版只优先服务一类用户：**需要频繁阅读、研究和整理网页内容的个人创作者或研究者**。

典型场景：

1. 用户在 Chrome、Brave 或 Edge 中打开一篇已经合法可见的文章。
2. 用户点击 LinkDigest 扩展，选择“总结”或“发送到 APP”。
3. Mac APP 展示提取到的标题、来源、正文和完整性提示。
4. 用户使用自己的 OpenAI-compatible 模型生成总结或翻译。
5. 原文、结果和执行证据保存在本机，并可导出为 Markdown、纯文本或 JSON。

### 2.2 核心问题

- 登录后或动态渲染的页面，服务器重新抓 URL 经常只能得到登录壳或空页面。
- 纯浏览器扩展不适合承担长期历史、模型配置、诊断和导出。
- 固定模型端点会带来地区、成本、隐私和可用性限制。
- 多数总结工具无法说明正文从哪里来、是否完整、失败发生在哪一层。

### 2.3 用户承诺

- **眼前可见优先**：优先处理用户当前已打开的页面 DOM。
- **先获得价值**：P0 不要求注册账号。
- **数据默认本地**：原文、结果、历史和 API Key 默认不经过 LinkDigest 云端。
- **模型可替换**：用户可以配置自己的 OpenAI-compatible Base URL、API Key 和模型名。
- **失败可恢复**：提取、连接、模型和存储错误必须给出人话原因和下一步动作。

## 3. 已确认的第一版技术方向

| 区域 | 决定 | 原因 |
|---|---|---|
| macOS APP | Swift + SwiftUI | 第一版只做 Apple 平台，原生 UI 是产品价值的一部分 |
| 平台补位 | 少量 AppKit | 富文本、窗口、菜单或 SwiftUI 明确不足时局部桥接 |
| Chromium 扩展 | TypeScript + WXT + Manifest V3 | 浏览器扩展生态仍以 Web 技术为主 |
| 跨端交接 | Native Messaging + 版本化 JSON | Swift 与 TypeScript 不共享源码，只共享可验证协议 |
| 本地数据 | SQLite | 单文件、事务可靠、适合 local-first 历史 |
| 秘密 | macOS Keychain | API Key 不进入 SQLite、日志、导出或 Git |
| 模型调用 | URLSession + Swift Concurrency | 使用系统原生网络与取消机制 |

技术边界不是永久锁死：如果 release spike 证明 Native Messaging、签名、公证或 SQLite 组合不可接受，再比较替代方案。Windows 不作为 P0 约束。

## 4. 核心循环

```text
浏览器当前页
  → 用户主动点击扩展
  → 提取当前 DOM / 选区
  → 版本化 JSON 交给 Mac APP
  → 用户检查来源与正文
  → BYOK 总结或翻译
  → 本地保存
  → Markdown 导出
```

云端、账号和同步不在这条链路中。任何未来云服务都不得成为打开本地数据或运行 BYOK 的前置条件。

## 5. P0 范围

### 5.1 必须完成

- macOS SwiftUI APP 可以启动、退出并恢复主窗口。
- Chrome、Brave、Edge 扩展可以读取用户主动触发的当前页面。
- 扩展发送 URL、标题、选区、正文、字符数和捕获证据。
- 无目标视频的纯文本页面继续发送 V1；检测到目标视频后发送独立 `CaptureEnvelopeV2` 与 `MediaDescriptor`，支持 direct MP4/MOV、HLS、blob/MSE、未加载、DRM/不支持类型与多视频歧义的真实能力分类。
- Native Messaging 可以完成握手、版本检查、超时和错误返回。
- APP 创建 `Task` 与 `ContentSnapshot`，展示来源、正文和完整性。
- 支持一个 OpenAI-compatible Chat Completions 模型连接。
- API Key 只写入 Keychain，界面、日志和导出不回显完整值。
- 首次向某个模型目的地发送网页标题和正文前，显示 Base URL/host、模型、模式与本地数据边界；取消不得创建 Run 或调用 Provider。
- 设置页可用极短 `Reply with OK.` 请求测试当前连接，明确可能产生极少模型用量，不创建 History/Run/Artifact 或保存回复。
- 支持总结、翻译、停止、重试和保存部分结果。
- SQLite 保存任务、正文快照、运行记录和结果。
- 支持打开历史、删除单项和导出 Markdown、纯文本（`.txt`）和 JSON。（2026-08-14 真机确认：实际产品已在此基线上扩展 PDF 与 Word(.docx) 导出，见 §5.3。）
- 手动公开链接按三分流生产实现：普通公网且无显式系统代理使用 `PeerBoundNetworkWebPageFetcher` / `Network.framework`，它把 policy 已核验的 numeric IP 绑定为实际 peer，并保留原 hostname 的 HTTPS SNI、`SecPolicyCreateSSL`、HTTP Host、system trust 与禁用 trust 网络补取；显式系统 HTTP(S) 代理或 DNS 全部返回 `198.18.0.0/15` fake-ip 时使用 `SystemProxyWebPageFetcher`。系统代理是**独立信任边界**：Foundation/代理可能重新解析 hostname，本机 URL/DNS admission 不能证明代理实际 peer，因而不宣称与 PeerBound 等价，剩余 proxy-resolution SSRF 风险由系统代理/VPN 所在环境承担。代理路线仅接受 HTTPS，拒绝 HTTP 并提示使用浏览器扩展；两路线均在每次 redirect 重新检查 URL、私网/test-net、凭据 URL、标准端口与 HTTPS→HTTP 降级。`URLSessionWebPageFetcher` 仍为 test-only legacy，不是 production fallback。
- Cloud API 完全不存在或断网时，以上能力仍可使用。

## 6. v0.1 垂直链路

第一条链路只证明最危险的跨进程交接，不同时解决所有产品能力。

## 8. 关键界面

### 8.1 主窗口（2026-09-06 层级重构）

主窗口使用原生三栏：主导航、当前范围列表、阅读或编辑详情。

- 主导航区分资料、笔记与博主；资料保留全部、最近、待总结、收藏，平台和标签为次级筛选。
- 博主目录保留在中栏，右侧展示选中博主的已保存作品；进入时恢复本会话上次有效选择，无历史选择则选第一位。点作品进入阅读，使用「返回作品」回到该博主作品列表。搜索无匹配显示对应空状态，不保留被隐藏博主的作品；尚未保存作品时提供抓取入口。博主目录行只展示头像、姓名和简短的「平台 · 作品数」，移除逐行重复的抓取按钮，选中博主页头保留「抓取作品」入口；置顶位于右键菜单并显示已置顶状态。
- 博主资料展示目标主页的真实显示名和头像，不使用字母或名称缩写代替头像。提供「更新资料」入口，已有博主无须保存新作品即可更新姓名与头像；获取失败明确显示未获取并支持重试，不以空值覆盖已有资料。作品受登录限制时，已公开可见的目标博主资料仍可单独更新。
- 博主作品卡片（X、抖音、小红书、B站）统一采用2.35:1封面框，图片等比填满并裁切，封面贴卡片顶部及左右边，不拉伸、不添加容纳留边。选择、排队及已保存卡片共用布局：文字区10pt内边距、两行标题预留、一行日期、底部一行平台真实指标，不缩字、不换行；加载与补全状态覆盖封面。按作品区宽度显示1–4列，常用2–4列；批次卡片与已有作品连续排列。日期显示年月日与来源提供的时分，无发布时间的已保存卡显示保存时间，未保存卡显示发布时间待获取，不补造时间。缺失指标显示—，真实0保留；本地封面优先，未获取、加载中、失败与文字预览分别表达。
- 互动数据使用本条作品保存时的实际值：抖音显示点赞、评论、收藏、转发，不虚构播放量；X 显示点赞、回复、转帖、书签、浏览；B 站显示播放、点赞、评论、收藏；小红书显示点赞、评论、收藏、分享。平台未提供或旧记录缺失的值显示短横并说明未提供，真实零显示 0；不将保存时数据描述为实时数据。
- 列表保留标题、作者或来源、时间及必要处理状态。搜索提示跟随当前范围，活动条件可移除；在笔记中清除搜索仍停留在笔记。
- 阅读详情按标题、来源、内容组织。长标题可展开保留全文，互动数据与运行详情按需展开。正文不套多余外卡，引用、代码和媒体仍保留专用呈现。
- 原文、总结和译文切换只显示已有结果；生成操作明确标注，沿用既有模型授权与排队逻辑。视频不可播时提供恢复和原页面入口。
- 独立空笔记直接编辑，生成操作位于已有正文之后；文章批注明确归属于当前内容。
- 添加菜单同时提供内容链接与博主主页。导入按输入、发现、选择组织，页脚说明选中、可保存、已加载和已保存数量，并显示保存结果。
- 主页所选作品成功入队后，关闭选择弹窗并定位到该博主右侧作品区，一次预留整批卡片，继承已有封面、配文、日期和统计。正式抓取串行；排队、抓取、保存原位更新，等待与执行显示转圈，失败、取消、中断停止动画。卡片身份与顺序固定，成功后替换为真实已保存作品；只有成功提交才增加资料数，不能重复显示或重复保存。
- 批次保存不自动进入正文，也不抢走当前阅读。用户手动点已完成卡片才阅读，返回抓取批次恢复队列位置；失败可单项重试、未提交项可取消、结果可手动收起。切页不丢任务；重启后未完成项标为已中断，用户点击继续才恢复，不自动重新请求。
- 抖音主页统计优先读取当前页面正常加载的作品列表响应，按作品和作者身份匹配；仅缺失字段进入详情补全，结构化结果优先，视频与图文 DOM 分别兜底。部分字段立即显示，真实 0 保留，未知值不覆盖已知值；使用短时缓存、去重和总超时，登录、验证、限流时暂停补全并明确提示。正文保存不等待统计齐全；缺值显示尚未读取，不推断为平台未提供。视频下载仍需勾选，不自动总结或转写。
- 多选面板显示数量和当前范围，既有结果跳过；部分失败可重试选中项，仍经过原有计划与确认。更多菜单分组保留复制、五种格式导出、重新处理与删除确认。
- 专注阅读隐藏前两栏且可退出；窄窗口的次要操作可换行。配色、字体与间距沿用共享主题和设计令牌，保留用户字体偏好。

### 8.1.1 设置窗口

设置按五类用途归组，原子页及其保存行为保留：

- AI与处理：模型与识别、生成偏好。
- 阅读与外观：外观、按功能开关显示的实验室。

- 显示当前页面是否可捕获。
- 展示标题、正文字符数和捕获范围。

## 9. 状态与失败语义

| 阶段 | 用户可见状态 | 主要恢复动作 |
|---|---|---|
| 页面捕获 | 可捕获、内容过少、受限页面 | 等待加载、选择文字、切换普通页面 |
| Native Messaging | 未安装、APP 未运行、版本不兼容、超时 | 打开 APP、重新检测、升级对应组件 |
| 正文 | 完整正文、当前可见、选区、未知 | 查看原文、重新捕获 |
| 模型 | 401、限流、协议不匹配、网络中断 | 更新 Key、切换模式、重试 |
| 存储 | 可写、只读恢复、保存失败 | 立即导出、备份、修复目录 |

APP 已运行时，Host 把校验通过的消息交给 APP，SwiftUI 更新当前页面状态。APP 未运行时，Host 不负责自动启动 APP，也不保存正文等待稍后处理；它返回 `APP_UNAVAILABLE`，并给出 `open_app` 动作，用户打开 APP 后重新发送。

错误对象至少包含：

```text
category / code / retryable / action / safeDetail
```

`safeDetail` 不得包含 API Key、Cookie、Token、完整私人 URL 或正文。

## 10. 数据边界

| 数据 | P0 默认位置 | 禁止 |
|---|---|---|
| API Key | macOS Keychain | SQLite、日志、测试夹具、导出、Git |
| 发送确认记录 | 本机 UserDefaults，仅含规范化 Base URL、host、模型、API 模式 | API Key、Keychain reference、正文、标题、运行记录 |

| 导出文件 | 用户选择的位置 | 包含 Key、Cookie、Token 或本机秘密路径 |

### Agent 通过本地 MCP 操作汲作（2026-09-06）

- 安装完整 App 后，设置的“连接”分组出现“MCP 连接”。默认关闭；用户可分别允许“抓取与整理”“转写与总结”。
- 提供“复制连接说明”“复制 JSON 配置”、服务状态、最近工具调用时间和名称。说明可直接交给本机 Agent，由其转换为客户端所需的 MCP 配置；不要求安装 Skill、Node 或 Python，不自动改任何 Agent 全局配置。
- 适用客户端必须支持本地 stdio MCP，App 必须运行。仅支持远程 URL 的云端客户端不在本版本连接范围。实际安装路径变化后重新复制配置。
- 工具覆盖：连接状态、搜索和分段读取资料、提交内容链接、查询捕获结果、查询博主、发现抖音、小红书、X 和 B 站主页作品、继续/停止发现、保存明确选择的作品、下载视频、本机视频转写、处理状态、总结、标签、收藏和打开记录。
- 多个博主依次执行；支持抖音、小红书、X、B 站完整主页；按当前页面可见作品有界加载，不承诺一次读全或严格按发布时间排序。B 站仅投稿视频，X 仅本人帖子，小红书仅本人笔记。登录、验证、页面变化与空列表分别说明；公开主页可读性仍取决于站点当前状态。发现结果不是已经入库；保存入队不是完成；必须查询已保存记录，再查询转写/生成终态。需要登录、验证、模型下载或数据发送授权时明确交回 App 处理。
- 不通过 MCP 提供删除资料、任意命令、凭据读取或模型凭据修改。关闭 MCP 会拒绝新调用，但已经提交的保存和处理任务继续运行。
- 验收：完整安装包包含 MCP 程序；复制出的路径可启动并握手；调用 `jizuo_status` 真正连接 App；未授权写入被拒绝；授权后修改在本地库和 App 可见；关闭后无法继续调用。平台网络、模型下载和真实媒体转写需单独标记验收结果，不以协议测试替代。

#### MCP 统计与状态精度（2026-09-06）

- `jizuo_statistics` 一次返回与侧栏一致的采集资料总数、平台类别和条数，笔记/作品单列，平台分类含待分类。直接复用数据库导航计数，不让 Agent 下载全量标题统计。
- 搜索返回 `source_host`、`platform`、`platform_name`；平台别名使用 App 统一映射。
- 捕获返回 `saved`、`download_status`、`is_terminal`、`capture_completeness`。正文已保存不代表视频下载成功，未知或从未提交的任务不报完成。下载状态记录仅当前进程有效，旧资料返回 available/unknown，不伪造本次下载结果。
- 转写返回结构化状态、是否结束、是否需用户操作；重启后通过持久化完成状态确认结果，遗留 running/pending 无活动任务时报告 interrupted。生成任务附带 run_id、is_terminal 与 has_result。发现任务返回请求上限、候选总数、返回数量和停止原因。

- 博主主页会话：抖音、小红书和 B 站复用 App 已有隔离登录分区；X 使用仅供渲染主页的独立分区，由用户主动登录、可在站点登录设置清除，不导入浏览器 Cookie、不重放私有接口。单条 X 解析仍使用现有公开读取。在设置中登录一次后，后续导入复用对应分区；登录失效或平台验证时在当前导入流程中完成并继续原主页。设置中的登录已保存不等于服务端已验证有效。发现不自动保存作品或触发模型；保存可选下载，转写要求已有可用本地媒体并由用户或已授权 MCP 任务触发。
- X 浏览器主页读取：站点登录页提供「在浏览器中登录 X」与浏览器支持入口。Google/Apple 登录使用用户默认浏览器中的 X 官方登录流程，不转移 App 内 OAuth 参数、Cookie 或凭据。浏览器与 App 内会话相互独立。
- 浏览器扩展只在用户主动读取 X 博主主页时传回该作者的可见作品候选；App 只展示内存选择清单，用户勾选保存后才入队，默认不下载、不总结、不转写。更多作品由用户在浏览器滚动后再次读取；不承诺全历史。扩展送达回执与最近送达记录不等同于窗口已展示、浏览器在线或登录仍有效。


抖音原文完整性补充（2026-09-07）：配文及话题保留在正文，即使其与页头标题相同；视频封面从当前作品身份对应的封面字段保存，不能借用推荐内容。重新抓取已有资料保存新快照，保留旧版本，不自动下载视频或启动 AI 处理。


跨平台标题/配文规范（2026-09-07）：独立原标题优先保留；抖音及被识别为正文切片的普通X帖以配文首句作为导航名称，最多40个Character后加省略号；明确X文章保留原标题。无标题时从实质正文提取，无文字则采用作者或平台与已有日期兜底，不编造媒体类型或时间。阅读页保留完整配文及话题，只去合成的同名Markdown标题；若当前配文全文与名称相同则隐藏重复大标题。派生名称不写回原始快照，不改变导出原文，也不调用AI。小红书、B站、YouTube、微信及一般文章已有独立标题不按首句截断，用户笔记和总结标题不受影响。


### 2026-09-07 四平台卡片与阅读一致性

# LinkDigest 任务学习模板

除纯格式或拼写修正外，每个开发任务都从本模板复制一份到任务说明、Issue 或当次开发记录中。目标是让功能交付和知识获得在同一条流程里发生。

## 1. 任务卡

- 任务名称：（任务开始时填写）
- 用户场景：（用户为什么需要它）
- 本次只解决：（一句可验收的结果）
- 明确不做：（防止任务膨胀）
- 当前状态：未开始 / 实施中 / 工程完成

## 2. 角色与交接

先画出本次任务所在的最小数据流，使用真实组件名和交接物：

```text
用户动作
   ↓
组件 A：负责什么
   ↓ 交接：什么数据
组件 B：负责什么
   ↓
用户可观察结果
```

必须回答：

- 谁是这次任务的入口？
- 每个组件只负责什么？
- 上一步具体把什么交给下一步？
- 哪一步失败时用户会看到什么？

## 6. 过程讲解与可选跟做（5–15 分钟）

AI 在实施相应组件时就要完成讲解，不把以下内容留成课后作业。可选跟做步骤用于共同观察，不是任务关闭门槛：

1. 当前场景为什么需要这个组件。
2. 它接收什么、输出什么、上下游是谁。
3. Syc 此时可以观察到什么现象。
4. 如果一起制造一个小错误，会看到什么以及如何恢复。
5. 想继续深入时，建议单独学习哪个最小主题。

自动化测试和工程证据仍用于证明产物正确；可选跟做只服务于理解。Syc 无需独立复述、提交答案或完成操作后，AI 才继续开发。

## 7. 工程验收与讲解交付

### 工程验收

- [ ] 用户场景已跑通。
- [ ] 正常路径和至少一个失败路径已验证。
- [ ] 测试、日志或截图证据已记录。
- [ ] 没有把凭据、Cookie、Token 或真实账号数据写入仓库。

### 过程讲解交付

- [ ] AI 已解释本次核心组件解决什么问题。
- [ ] AI 已说明它在工作流中的位置、上下游和交接物。
- [ ] AI 已说明正常现象、失败表现和恢复方式。
- [ ] 可选跟做动作足够具体，但未被设置为阻塞门槛。
- [ ] 新名词已按需加入 `GLOSSARY.md`。
- [ ] 过程讲解和可选深挖入口已写入 `LEARNING_LOG.md`。

工程验收和过程讲解交付都完成后，任务即可标记为工程完成；不要求 Syc 额外交作业。Syc 主动提出不理解的内容时，可在当前对话简要补充，或另开小窗口深挖。

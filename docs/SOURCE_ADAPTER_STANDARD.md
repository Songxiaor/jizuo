# 内容来源接入标准

本标准适用于以后新增或扩展任何文章、帖子、视频、图集和订阅来源。质量基线是当前的**抖音单条内容链路**与 **X 单帖链路**：不是“能识别平台”就算完成，而是从当前页面到 App 详情页都能交付同一条内容的核心数据和媒体。

## 1. 单条内容边界

- 先确认当前 URL 对应的内容实体和稳定 ID；列表、推荐流、问题页外壳不能冒充单条内容。
- 作者、发布时间、互动数和媒体必须从同一条内容的 DOM 范围读取。
- 不混入页面级、问题级或账号级统计。例如抓知乎回答时，不得把整个问题的浏览量写成回答浏览量。
- 登录受限页面优先读取用户已打开、已渲染的 DOM；不静默读取完整 Cookie 数据库，不绕过平台访问控制。

## 2. 标准交付字段

能稳定读取时至少交付：

| 类别 | 字段/表现 | 规则 |
|---|---|---|
| 身份 | 平台、canonical URL、内容 ID | 指向单条内容，不保留推荐流壳地址 |
| 正文 | 标题、正文/说明 | 清除导航、推荐、评论区和订阅弹窗 |
| 属性 | `author`、`published` | 写入 frontmatter，在 App 顶部属性条展示 |
| 互动 | `likes`、`comments`、`shares`、`collects`、`views` | 只写当前内容可确认的口径；缺失就省略，不猜 |
| 图片 | 正文顺序中的 Markdown 图片 | 优先 `data-src/srcset/picture` 的最佳候选，过滤头像和页面装饰 |
| 视频 | `MediaDescriptor` 与即时下载结果 | 临时播放地址不得进入持久化、日志或夹具 |

扩展侧和 App 侧统一使用上表字段名。平台自己的叫法在提取层映射，例如 X 的 replies → `comments`、reposts → `shares`，知乎的赞同 → `likes`。

## 3. 端到端交接

```text
当前浏览器页面
  → 平台适配器：锁定单条内容，提取正文、属性、互动和媒体
  → CaptureEnvelope：只交接已有的语言中立字段
  → App 入库：保存正文与来源快照
  → 图片/视频本地化：下载可公开访问的媒体并绑定 snapshot
  → 详情展示：顶部属性、互动数据、正文和媒体都可见
```

`extractCurrentPage` 与 `extractPageInIsolatedWorld` 是同一适配器的测试版和生产注入版，两份逻辑必须同步。只改其中一份，自动测试通过也不能算接入完成。

## 4. 每个平台的最低测试

- 一个脱敏成功夹具：核心属性、正文、互动和媒体按预期交付。
- 一个登录受限场景：给出可解释失败，不回退抓取整页外壳。
- 一个平台变化场景：关键选择器缺失时省略未知字段，正文仍安全，不能串到相邻内容。
- 测试版与生产注入版对同一夹具输出一致。
- 含图片的平台验证最佳图片 URL、CDN 请求头、本地缓存和详情展示；含视频的平台验证媒体分类与即时保存。

## 5. 真机完成条件

1. 在现有 Brave 窗口打开一条当前真实内容并重新抓取。
2. 扩展弹窗显示正确的平台、标题与可捕获状态。
3. App 新产生的历史记录顶部显示作者/时间/可确认的互动数。
4. 正文干净，图片按正文顺序显示；视频能播放或给出明确限制。
5. 检查抓取结果没有混入推荐内容、页面级统计、Cookie、Token 或临时签名地址。

旧记录、旧扩展构建、只看源码或只跑夹具都不能代替这一步。若不清楚该怎么实现，先检查抖音精确单条分支和 X 单帖分支的代码、测试与当前真机表现，再设计新适配器。

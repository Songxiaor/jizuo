# 新机测试指南（LinkDigest ad-hoc 本地测试版）

> 面向：把当前开发版拷到另一台 Mac 做真实手工测试。
> 这是 **ad-hoc 签名、未公证**的开发自测版，不是发布版；只供自己测试，不要外发。

## 前提

- **Apple Silicon（arm64）** 的 Mac。
- **macOS 26+**（本机转写用 Apple 的 zh_CN 语音资源，需要 26；低版本 App 能开但转写不可用）。
- 一个 `LinkDigest-newmac-test-*.zip` 测试包（在开发机上用下面「如何重新打包」生成，取最新的一个）。

包内含三样：`LinkDigest.app`、`LinkDigest-extension-0.2.0/`（扩展文件夹）、本说明的简版 txt。

---

## 启用流程

### 1. 装 App

1. 删掉旧的 `/Applications/LinkDigest.app`（如果有）。
2. 把 zip 拷到新机（AirDrop / U 盘），双击解压。
3. 把 `LinkDigest.app` 拖进 **「应用程序」**。
4. 打开 Terminal，去掉隔离标记（否则会触发 App Translocation 崩溃）：
   ```bash
   xattr -cr /Applications/LinkDigest.app
   ```
5. 双击打开。**不要** `sudo`，**不要**关 Gatekeeper。

### 2. 装浏览器原生 Host（浏览器抓取的前提）

6. App → 右上角 **设置** → **浏览器支持** → **安装**（把 Native Host manifest 写进浏览器 profile）。

### 3. 装扩展

7. 浏览器扩展页（`brave://extensions` / `chrome://extensions` / `edge://extensions`）→ 打开 **开发者模式**。
8. **加载已解压的扩展程序** → 选 `LinkDigest-extension-0.2.0` 文件夹。
9. 工具栏出现 LinkDigest 图标即成功。

### 4. 配置模型（BYOK）

10. App → 设置 → **模型与识别** → **添加模型 → 选择服务商** → 选服务商（如 **阶跃星辰**）→ Base URL 自动填入 → 填 API Key → 选模型。

### 5. 首次转写（按需）

11. 第一次对视频转写时会弹「下载 Apple 中文离线模型」→ 点 **下载并转写**。这是一次性的系统级资源，装好后不再提示。

## 已知限制（不是 bug）

- **X 视频不能下载到本地**：X 是 HLS/MSE 加密流媒体，天生没有可直链下载的单个 MP4；只有抖音这类直链 MP4 能落地本地。
- **手动粘贴链接 / 剪贴板**按钮是灰的（功能未完成）。
- ad-hoc 未公证；首次打开需 `xattr -cr` 去隔离。

## 常见问题排查

**打开就崩，报 `Bundle.module` / `LinkDigest_LinkDigestCore.bundle` 找不到**
资源包没放到 app 根目录。用最新测试包（打包时已把资源包补到 `LinkDigest.app/` 根目录）。这是打包器 `build_app_bundle` 把资源放进 `Contents/Resources/`、而运行时按 `Bundle.main.bundleURL` 找根目录导致的；开发机因有 `.build` 兜底路径不暴露，换机才崩。

**打开崩溃，路径是 `/private/var/folders/*/…AppTranslocation…`**
没去隔离标记，被 Gatekeeper 路径随机化。跑 `xattr -cr /Applications/LinkDigest.app` 后重开。

**抖音「视频自动保存失败：视频暂时无法下载」**
抖音 CDN 对非浏览器 User-Agent 返 403。最新包已给媒体下载补上浏览器 UA；用最新包即可。

**点红「L」显示「同步失败/扩展未响应」**
MV3 service worker 冷启动时首个消息可能丢或被拒。最新扩展已改成自动重试一次；再点一次通常即成。若持续失败，看 `扩展页 → LinkDigest → Service Worker → Console` 的红色报错定位。

**扩展抓取时提示「App 未连接」**
Native Host 没装或没连上。回到第 2 步在 App 的「浏览器支持」里安装。

## 如何重新打包（在开发机上）

当前 local-test 发布管线锁定在旧的冻结候选、打不了含新功能的当前分支，所以用轻量 ad-hoc 路径：

```bash
# 1. 构建 App + Host + 扩展到暂存目录（不覆盖日常 ~/Applications 的 App）
python3 scripts/build-and-deploy-local.py --replace \
  --app-destination <暂存>/LinkDigest.app \
  --extension-destination <暂存>/LinkDigest-extension-0.2.0

# 2. 把 SwiftPM 资源包补到 .app 根目录（否则换机崩），再 ad-hoc 重签
cp -R <暂存>/LinkDigest.app/Contents/Resources/LinkDigest_LinkDigestCore.bundle <暂存>/LinkDigest.app/
cp -R apps/desktop/.build/arm64-apple-macosx/release/GRDB_GRDB.bundle <暂存>/LinkDigest.app/
codesign --force --deep --sign - --identifier com.syc.linkdigest <暂存>/LinkDigest.app

# 3. 只改了扩展时，只重建扩展即可（不必重编 Swift）
pnpm --filter @linkdigest/browser-extension build
# 产物在 apps/browser-extension/.output/chrome-mv3

# 4. 用 ditto 打 zip（保签名）
ditto -c -k --sequesterRsrc --keepParent <暂存目录> ~/Downloads/LinkDigest-newmac-test-<日期>.zip
```

> 注意：`build_app_bundle` 把资源放进 `Contents/Resources/` 是待修的根因；步骤 2 是绕过。正规修法（让签名也干净）需要单独处理。

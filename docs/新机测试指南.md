# 汲作 v0.2.24 新机测试指南

> 当前 GitHub 安装包使用 ad-hoc 签名、尚未公证。首次打开需要在 macOS“隐私与安全性”中确认一次；不需要关闭 Gatekeeper，也不需要执行 `sudo` 或清除 quarantine。

## 1. 选择正确安装包

- Apple 芯片（M1/M2/M3/M4/M5）：`Jizuo-0.2.24-macOS-Apple-Silicon.dmg`
- Intel 芯片：`Jizuo-0.2.24-macOS-Intel.dmg`

在“关于本机”里查看“芯片”或“处理器”即可判断。两个 DMG 是独立单架构版本，不再发布一个 Universal 安装包让用户自行猜测。

## 2. 安装 App

1. 打开 DMG，把 `汲作.app` 拖进“应用程序”。
2. 双击 `汲作.app`。首次被系统拦截时，点“完成”或“好”。
3. 打开“系统设置 → 隐私与安全性”，在页面底部找到汲作，点“仍要打开”。
4. 再确认一次，之后可正常从“应用程序”启动。

新电脑首次启动时，“全部”应为 **0 条**。汲作的历史只读取本机 `~/Library/Application Support/LinkDigest/`，不会打进 DMG，也不会从 GitHub 自动同步。

## 3. 安装浏览器扩展

1. 汲作 → 右上角“设置” → “浏览器支持”。
2. 点“打开扩展文件夹”。App 会把内置扩展原子导出到：
   `~/Library/Application Support/LinkDigest/汲作浏览器扩展/`
3. Finder 会自动打开并选中该文件夹。
4. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”。
5. 点“加载已解压的扩展程序”，选择 Finder 刚才选中的“汲作浏览器扩展”。
6. 回到汲作的“浏览器支持”，点 Chrome 右侧“连接”。

扩展源文件已经包含在 `汲作.app/Contents/Resources/BrowserExtension/` 中，所以把 App 从 DMG 拖到“应用程序”后仍可导出；不再依赖 DMG 旁边的临时文件夹。

## 4. 配置与验证

1. 在“设置 → 模型与识别”中配置自己的 OpenAI-compatible Base URL、模型名和 API Key。
2. 打开一篇普通网页，在 Chrome 工具栏点击汲作扩展并发送。
3. 回到 App，确认“全部”新增 1 条，并能打开原文。
4. 对该记录运行一次总结，确认模型配置可用。

## 5. 开发机重新打包

```bash
ps auxww | rg 'swift|swift-frontend'
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  python3 scripts/package-dmg.py --version 0.2.24 --ad-hoc
```

脚本会先构建并验证 universal 中间产物，再分别抽取 arm64 与 x86_64 切片、重新签名，最终在 `dist/` 生成两个使用“汲作”名称的 DMG。

有 Apple Developer 会员、Developer ID Application 证书和已保存在 Keychain 的公证凭据后，正式分发使用：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  python3 scripts/package-dmg.py --version 0.2.24 \
  --signing-identity "Developer ID Application: <开发者名称> (<Team ID>)" \
  --notary-keychain-profile "jizuo-notary"
```

证书和公证密码只保存在 macOS Keychain，不写入仓库、命令参数或发布日志。只有显式传入 `--ad-hoc` 才会生成测试包；缺少正式分发参数时脚本直接停止，不会伪装成已公证版本。

# LinkDigest V0.1 实施与验收记录

> 当前结论：自动化链路与 Chrome、Brave 的真实加载、扩展触发、离线错误、在线接收和 20 次 Release p95 已完成；Edge 本机未安装，是 V0.1 浏览器矩阵唯一未完成项。正式 Host 稳定目录、Developer ID 签名与公证属于后续 release spike，不是本任务关闭门槛；当前 `/tmp` 路径不得当成发布方案。

## 1. 场景、角色与交接

```text
固定测试文章
  → Popup：展示标题和字符数，接收用户点击
  → injected content function：读取 selection / article / main / body
  → MV3 background：执行 JSON Schema + semantic invariant
  → LinkDigestNativeHost：Chromium framing、上限、超时和错误映射
  → Unix domain socket：交给正在运行的 APP
  → Application inbox：幂等接收并更新 MainActor 状态
  → SwiftUI：显示连接、标题、URL、捕获方式、完整性、字符数和正文
```

View 不直接接触 socket 或文件系统。Host 不提取网页、不调用模型、不保存正文，只搬运已校验的消息并返回结构化结果。

## 2. 合同选择

唯一跨语言合同是 `contracts/capture-envelope-v1.schema.json`（JSON Schema Draft 2020-12）。

- TypeScript 在构建时由 Ajv 2020 standalone generator 生成静态校验函数；扩展运行时不执行 `eval` / `new Function`。
- Swift 从 Package resource 加载并执行同一 Schema 的结构规则。
- `characterCount == Unicode scalar count` 等跨字段条件作为 `x-semantic-invariants`，两端使用同一算法和 fixtures 验证。
- `scripts/check-contract-sync.sh` 确认 Swift resource 与根合同字节一致；`generate-contract-validator.mjs --check` 确认扩展静态校验器与根合同一致。

选择 JSON Schema 是因为当前最重要的是 Swift 与 TypeScript 共享可执行合同；如果未来字段规模大到手写模型维护成本明显上升，再评估受控代码生成。

## 3. Native Host 与 APP 状态

- Host 名称：`com.syc.linkdigest.v01`。
- Chromium framing：4-byte little-endian 长度 + JSON body。
- frame 上限：4 MiB；正文上限：2,000,000 Unicode scalars。
- Host stdin、Host→APP、APP accepted client 都有 10 秒有界超时。
- APP 运行：Host 通过 `/tmp/linkdigest-<uid>.sock` 交接。
- APP 未运行：返回 `APP_UNAVAILABLE/open_app`，不自动拉起。
- Host 未安装：Chromium API 失败映射为 `NATIVE_HOST_NOT_FOUND/open_install_guide`。
- 半包不结束：当前连接超时且与后续连接隔离。

普通日志不写正文、完整私人 URL、Cookie、Token 或 Key。

### 3.1 Native Host 安装与卸载脚本边界

- `scripts/native-host/install-dev.sh` 要求显式 `--browser chrome|brave|edge`；默认始终 dry-run，不提供 `all` 批量模式。
- Brave 150 当前 macOS 用户级查找映射到 Chrome 的 `Google/Chrome/NativeMessagingHosts` 目录，因此 `--browser brave` 与 `--browser chrome` 去重到同一个目标；不扫描或写入另一个品牌目录。Edge 只有显式 `--browser edge` 才允许写入其目标。
- 运行前校验 Host executable、同目录 `LinkDigest_LinkDigestCore.bundle` 和其中的合同 Schema；不通过则不创建目录、不写 manifest。
- `--apply` 写入时先对同 basename 文件创建唯一时间戳备份，再以 `chmod 600` 的同目录临时文件执行 rename 设计；输出 `TARGET` 与 `BACKUP`。自动检查确认 staging、目标和失败残留路径，但不把测试表述为系统级原子性证明。
- 临时文件写入由 `EXIT` trap 保护；若 chmod、写入或 rename 失败，临时文件不会自动删除，脚本会明确打印残留路径供人工处理。
- `scripts/native-host/uninstall-plan.sh` 永远只读，只打印精确目标、存在状态、同 basename 备份和人工 `rm`/恢复命令；不执行删除、覆盖、移动或恢复。

## 5. 真实浏览器验收

### Chrome 150：已完成

- 浏览器：Google Chrome `150.0.7871.47`，使用项目内隔离 Profile；未复用或读取日常 Profile。
- 扩展：真实“加载未打包”后 ID 为 `dpjfghbojjgoagocbjdpfpejhgfdojfh`，Service Worker 正常运行；生成 manifest 仍只有 `activeTab`、`scripting`、`storage`、`nativeMessaging`。
- 已按授权写入 `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.syc.linkdigest.v01.json`；写前目标由 dry-run 精确列出，未读取其它 manifest、Cookie、账号或历史。
- APP 未运行：工具栏真实点击后约 `86.8 ms` 返回 `APP_UNAVAILABLE / open_app`。
- APP 已运行：单次 Release 链路约 `93.8 ms` 返回“已发送”；SwiftUI Accessibility 与窗口证据同时显示 `Fixed Test Article`、测试 URL、`rendered_dom / full_article`、`68 字符`和固定正文。
- 连续 Release 发送：`20/20` 成功，失败 `0`，p95 `49.2 ms`，最小 `10.3 ms`，最大 `82.4 ms`。Host 只有在 SwiftUI model 完成接收后才写回 `taskAccepted`，因此该测量覆盖 background → Native Host → socket → App 接收。

真实浏览器现场还修正了两个自动化未发现的问题：

1. Ajv 在扩展运行时编译 Schema 会触发 MV3 CSP，导致 Service Worker 启动失败；现已改为构建期生成静态校验函数，并加入回归测试。
2. 浏览器启动的 Host 若位于 `Documents` 会触发 macOS TCC；只复制 executable 又会缺失 Swift resource bundle。Chrome 验收因此使用 `/tmp` 中成对暂存的 Release executable + `LinkDigest_LinkDigestCore.bundle`，隔离 Profile 的测试 manifest 指向该临时位置。正式安装必须把两者一起放进签名 App 或获确认的非隐私目录，不能从源码目录直接发布。

### Brave 150：已完成

- 浏览器：Brave `150.1.92.139`，项目隔离 Profile；日常 Brave PID 47965 始终未关闭、隐藏、点击或读取。
- 加载：Brave 150 暴露 experimental CDP `Extensions.loadUnpacked/getExtensions/triggerAction`。`loadUnpacked` 返回 ID `dpjfghbojjgoagocbjdpfpejhgfdojfh`，`getExtensions` 返回 LinkDigest `0.1.0 / enabled=true`，真实 Service Worker 与 Popup target 均出现；`triggerAction` 针对固定文章 tab 后 Popup 显示 `Fixed Test Article / 68 个字符`且发送按钮可用。
- APP 未运行：约 `71.1 ms` 返回 `APP_UNAVAILABLE / open_app`。
- APP 已运行：单次 Release 链路约 `55.9 ms` 返回“已发送”。
- 连续 Release 发送：`20/20` 成功，失败 `0`，p95 `34.9 ms`，最小 `9.7 ms`，最大 `70.1 ms`。
- Brave 150 的 macOS 兼容逻辑会把用户级 Native Messaging 目录覆盖为 Chrome 的注册位置，因此本次真正生效的是 `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/`，不是 Brave 自己的同名目录。验收前已让实际生效的 LinkDigest manifest 指向同一临时 Host，并在隔离浏览器中重新验证；这是 Brave 1.92.139 的现场与对应源码结论，不外推为所有未来版本的永久规则。

## 6. 失败、恢复与回滚

- 合同漂移：运行 `./scripts/sync-contracts.sh` 后复跑 `pnpm check`；不要手改 Swift resource 副本。
- APP 离线：打开 APP 后由 Popup 重试；Host 不保存正文排队。
- manifest 绑定错误：用正确 extension ID 重新 dry-run/apply；只处理 `com.syc.linkdigest.v01.json`。
- 路线失败：保留 Schema、fixtures、测试和证据；不得静默改回 Electron。路线反转必须先通过 Brain CLI 记录。

## 7. 下一阶段门禁

只有 Chrome、Brave、Edge 的真实浏览器验收、APP 已运行接收路径、APP 未运行恢复路径和 Release p95 完成后，才关闭 V0.1。模型、SQLite、Keychain、账号、云同步和正式视觉均不在本任务范围。

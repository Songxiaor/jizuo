### Edge 根因与脚本修复

Edge 使用 `--user-data-dir=/tmp/...` 时，用户级 Native Messaging manifest 的查找根是该 user-data-dir 下的 `NativeMessagingHosts/`；旧脚本只写默认的 `~/Library/Application Support/Microsoft Edge/NativeMessagingHosts/`，因此隔离 Edge 找不到 manifest。Microsoft Edge 官方 macOS 文档明确写明：用户级 Native Messaging Host 位于 user data directory 的 `NativeMessagingHosts` 子目录，见 [Microsoft Edge Native messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging#step-3-copy-the-native-messaging-host-manifest-file-to-your-system)。`install-dev.sh` 现在支持仅 Edge 使用的 `--user-data-dir /absolute/profile`，并把目标严格限制为 `<profile>/NativeMessagingHosts/`。Profile 必须是词法规范的现存绝对目录；从 `/` 到 Profile 的所有组件都拒绝 symlink，Chrome、Brave 传入该参数也会拒绝。

## Native Host 交付边界

浏览器启动源码目录中的 Host 会触发 macOS `Documents` TCC。仅复制 executable 又会缺少 `LinkDigest_LinkDigestCore.bundle`，导致合同资源不可用。本次真实验收把 Release executable 和 resource bundle 成对暂存到 `/tmp/linkdigest-v01-test-501/`，并让 Chrome/Brave 的 LinkDigest 测试 manifest 指向同一 Host。

这证明了垂直链路，但不是正式安装方案。发布前仍需把两者放入签名 App 或经 Syc 确认的非隐私安装位置，并验证备份、卸载、签名与公证。

## Native Host 脚本回归（隔离 HOME）

本轮安装边界修正后运行 `pnpm native-host:check`：

- `--browser` 缺失或传入 `all` 会拒绝；Chrome、Brave、Edge 必须显式选择。
- Brave 目标与 Chrome 目标去重到 `Google/Chrome/NativeMessagingHosts`，没有写入 `BraveSoftware` 目录；Edge 同时覆盖默认目录 dry-run、隔离 `--user-data-dir` 的精确直接子目录与实际写入。
- Edge Profile 专项验证 Profile 本身 symlink、父级 symlink、中间组件 symlink、`.`、`..`、重复 `/`、尾随 `/`、缺失 Profile 拒绝，以及失败后解析位置没有新增 `NativeMessagingHosts` 或 manifest。测试还验证目标文件 `0600`、覆盖前唯一时间戳备份、备份候选 symlink 不跟随和同目录 rename 设计；默认 HOME 路径继续覆盖既有目标组件与 manifest symlink 拒绝。
- 隔离目标在创建前、创建后和写入前复验，降低静态路径逃逸与可控竞态风险；测试不证明、文档也不声称完全消除恶意并发换链。
- 通过替换隔离测试中的 `mv` 验证失败临时文件由 trap 保留并打印路径；测试不自动删除残留。
- `uninstall-plan.sh` 输出目标状态、备份和人工命令；前后文件清单一致，未执行删除或其它写操作，最后只报告“不读取文件内容、不修改”。

测试沙盒由脚本创建并保留，命令输出会打印 `TEST_SANDBOX=...`；真实 HOME、真实浏览器目录和其它 manifest 未触碰。

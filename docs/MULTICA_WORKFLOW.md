# LinkDigest 在 Multica 中的协作方式

## 一句话

Multica 是 LinkDigest 的项目总控台；Codex 仍是底层执行引擎。Syc 默认只与“LinkDigest 总控与学习教练”沟通，总控负责拆解需求、创建分阶段 Issue、分派专业 Agent、汇总结果并同步过程讲解。

## 团队

| 角色 | 主要职责 | 不应自行决定 |
|---|---|---|
| 总控与学习教练 | 维护产品目标、拆解任务、控制阶段、解释名词、汇总验收 | 不替 Syc 决定付费、安装、凭据、隐私和发布事项 |
| UI/UX 设计师 | 用户流程、信息架构、界面规格、状态设计和视觉验收 | 不直接改变数据、安全或平台边界 |
| macOS 工程师 | SwiftUI、Keychain、Native Host、模型运行和 macOS 集成 | 不绕开设计规格或秘密边界 |
| 浏览器与提取工程师 | Chromium 扩展、当前页提取、平台适配、字幕和媒体链路 | 不默认读取完整浏览器 Cookie 数据库 |
| 数据与后端架构师 | SQLite、历史、导出、迁移；远期服务端边界 | 不因远期规模提前引入服务器和云端 |
| QA 与发布审查 | 测试、安全、许可证、浏览器矩阵、PR 和发布门禁 | 不用审查结论替代 Syc 的最终产品决定 |

## Syc 的默认入口

1. 产品想法、优先级、路线、名词解释和“下一步做什么”：只找总控。
2. 总控把需求转换为父 Issue 和专业子 Issue，并选择负责人。
3. 专业问题已经存在对应 Issue 时，可以在该 Issue 中直接询问负责人；涉及范围或优先级的变化仍回到总控。
4. 安装外部软件、输入真实凭据、购买服务、签名、公证、上架和发布必须由 Syc 明确授权。

## Issue 启动规则

- `backlog`：已经规划但不启动 Agent。
- `todo`：准备执行；如果已分配给 Agent 或 Squad，会触发运行。
- `in_progress`：正在实施。
- `in_review`：等待独立验收或 Syc 决策。
- `done`：工程证据、过程讲解和学习日志均已交付。
- `blocked`：等待明确的外部条件或 Syc 授权。

总控使用 Stage 管理顺序：同一阶段可以并行；下一阶段默认保持 `backlog`，只有依赖满足后才提升为 `todo`。

## 每个非平凡任务的双轨合同

每个任务都必须同时交付：

1. 用户可观察的工程结果。
2. 自动测试或人工验收证据。
3. 实施过程中同步出现的场景、角色、交接和工具说明。
4. 最多 3–5 个新名词的人话解释。
5. 失败、恢复方式和明确非目标。
6. `docs/LEARNING_LOG.md` 更新；耐久决策按项目规则写入 Project Brain。

学习不是课后考试。Syc 可以随时说“不明白”或“用人话解释”，总控补充当前概念后继续主开发流程。

## 代码协作

- GitHub `main` 是代码真相源。
- 每个代码 Issue 使用独立工作区和分支，避免多个 Agent 直接写同一个本地目录。
- 代码变更默认通过 PR 交给 QA/发布审查。
- PR 标题或分支包含对应 Multica Issue key，确保自动关联。
- 原始 Codex 目录在迁移后作为首次基线来源，不再作为多个 Agent 并行写入的共享目录。

# LinkDigest 0.2.0 总检指南

> 适用对象：Loop 9 local-test integrated candidate 的 Syc 总检。此文会被逐字节复制到候选根目录 `ACCEPTANCE_GUIDE.md`；请以候选内版本为准。

## 总检前边界

- 这是 ad-hoc local-test DMG，不是 Developer ID 签名、公证或商店版本。不要关闭 Gatekeeper、不要使用 `sudo`、不要执行 `xattr` 清理或修改系统安全设置。
- 本指南中的浏览器安装是 Syc 主动的真实产品动作；工程自动化从不触碰真实 HOME、浏览器 profile、Keychain 或 Provider。开始前只保留自己愿意保留的浏览器/本地数据状态。
- API Key 只在 App 内主动保存。截图、反馈和记录表中不要包含 API Key、Authorization、Cookie、完整响应 body 或个人网页内容。

## 总检步骤

开始前：在候选根目录运行 `shasum -a 256 -c SHA256SUMS`，确认所有项均为 `OK`；把结果作为本轮总检记录的一部分保留。校验失败时不要打开 DMG，直接记录候选目录名和失败项。

> 当前 App/dev/preflight 已使用 Chrome/Brave shared active mapping；r2 transaction 与 r4 release-unit/local-test probe 尚保留 legacy independent-Brave contract，不能把旧候选的 release matrix 当作本映射的发布验收。下一次 candidate freeze 前必须完成版本化迁移。

| 步骤 | 操作 | 预期表现 | 失败时请保留 |
| --- | --- | --- | --- |
| 1 | 双击 DMG，在 Finder 中右键 `LinkDigest.app` → 打开；若系统提示，确认对象无误后在“隐私与安全性”选择 Open Anyway。 | App 正常启动，名称为 LinkDigest，版本为 0.2.0；设置、历史和手动链接入口可见。 | Finder/系统提示截图、macOS 版本、候选内 `SHA256SUMS` 核对结果。 |
| 2 | 打开“设置 → 浏览器支持”。 | Chrome、Brave、Edge 分别显示未安装、已安装一致、漂移或未知同名 manifest 等明确状态；未检测到目录时不会创建目录。 | 页面状态截图；不要手工编辑 manifest。 |
| 3 | 在 Chrome、Brave、Edge 三个支持行依次执行安装；Chrome 与 Brave 可任选先后，若 App 要求确认接管，核对说明后再确认。 | Chrome 与 Brave 都显示“已安装且一致”，并共享一个 Google/Chrome target；任一行的修复、卸载或恢复会同步另一行。Edge 保持独立。 | 每个浏览器行的前/后状态截图；若出现确认框，截取不含路径外隐私的提示。 |
| 4 | 在扩展管理页开启开发者模式，选择候选根目录 `extension/LinkDigest-extension-0.2.0-chromium.zip` 解压后的目录加载（浏览器只接受目录，不直接加载 zip）。 | 扩展名称为 LinkDigest；扩展 ID 与候选 `BUILD_MANIFEST.json` 中的 extension ID 一致；popup 可打开。 | 扩展详情页中 ID/错误区域截图；不要截取浏览历史或其它扩展。 |
| 5 | 在一条普通网页、X 或已登录页面各主动触发一次捕获。 | 扩展只处理当前页可见 DOM；App 收到捕获后显示标题、来源和正文长度。登录受限/失败时给出可恢复的人话提示，不要求导入密码或完整 Cookie。 | popup/App 错误文案、页面类型、是否已登录；不要提供 Cookie。 |
| 6 | 在“模型服务”配置自己的 Base URL、模型与 API Key，先点“测试连接”，再对一条捕获内容执行总结和翻译。 | Key 不回显；连接成功后总结/翻译显示流式进度与完成态。输出语言和可选翻译模型遵从设置。 | Base URL host（不要带 query）、模型名、固定本地错误文案和截图。 |
| 7 | 对一条成功总结等待自动标签；在历史详情手动增删标签，在侧边栏单选及 Command 多选筛选。 | 自动标签失败不影响总结完成；成功时当前详情与 chip 无需切换记录即可刷新；多选为交集。 | 历史详情/筛选空态截图与触发顺序。 |
| 8 | 在历史详情查看操作、模型、时间、usage；分别导出 Markdown、TXT、JSON。 | 旧记录缺 usage 显示“—”；费用不估算。导出包含标签，且不含 API Key/Cookie/Provider body。 | 导出格式与是否包含预期标签；不要上传导出正文。 |
| 9 | 回到浏览器支持页，选择一个已安装浏览器执行卸载；再刷新状态。 | 仅 LinkDigest receipt 绑定的 manifest 被删除；未知或漂移文件不会被硬删。 | 卸载前/后 UI 状态；若被拒绝，截取恢复指引。 |

### 可选 onboarding 观察项（不计入首次价值时间）

如需了解 onboarding 总耗时，可分别记录安装完成时刻与模型配置完成时刻；这只是独立观察项，**不得**与“首次价值时间”合并或提前其计时起点。

### 可辅助取数位置

- History 详情头部显示每次 Run 的操作、模型、创建时间、状态和 total tokens；hover/次级文本可查看 prompt/completion tokens。旧 Run 的 usage 是“—”，不是 0。
- History 的标签筛选、导出时间与完成状态可辅助复盘样本完成与复用，但不会替代人工的正文可用性判断。
- 不提供 BYOK 费用估算，因为任意模型没有可靠价格表；请不要用该候选推断成本。

## AI 速读卡

- 产品一句话：把 Chromium 当前页面或公开链接送入 local-first 桌面 APP，免登录完成可追溯的提取、BYOK 总结、翻译与导出，注册后再选择同步和托管能力。
- 核心循环：导入 → 提取 → 检查原文 → 总结/翻译 → 本地保存/导出 → 可选注册与同步。
- 目标平台：macOS 桌面端优先；Chrome、Brave、Edge 扩展；Windows 桌面端为后续候选。
- 硬约束：本地核心免登录、当前页面优先、Provider-neutral、内容默认不上云、失败可解释、禁止批量绕过平台访问控制。
- 推荐默认：TypeScript 主干；Electron + React、WXT MV3、Native Messaging、SQLite；云端使用 Fastify 模块化单体与 PostgreSQL。
- 发挥空间：视觉品牌、结果阅读体验、动效、空状态和摘要模板可以优化，但不能改变授权边界。
- P0 验收：不注册账号，在 Chrome 打开一篇文章，点击扩展后，桌面端显示提取正文并用 BYOK 模型完成总结或翻译，云端断开仍可查看历史和导出。
- 最容易翻车：为了未来增长让 P0 强依赖云端，或把“当前已登录页面提取”错误实现成服务器重新抓 URL。
- 超预期机会：用户能看见内容来源、数据去向和失败降级；注册是获得同步与托管权益，而不是解锁本地数据。

## 第一章：产品概述

LinkDigest 是一款面向全球用户的 local-first 链接理解桌面工具，让需要跨平台阅读的人能够从浏览器或链接直接获得可核查的总结与翻译，而无需先注册、接受固定模型端点、反复复制正文或把全部阅读历史交给产品服务器。

### 1.1 差异化对比表

以下比较基于 2026-07-13 已核对的公开仓库说明与本机 Sam 实际使用体验；平台能力会变化，进入开发前仍需用真实样本复测。

| 功能 | 相关产品/项目 | LinkDigest | 实现方式 |
|---|---|---|---|
| 登录受限内容 | 普通 URL 总结器通常从服务端重新请求 URL | 优先处理用户当前已登录、已经渲染的页面 | Chromium Content Script 提取 DOM，经 Native Messaging 交给本地 APP |
| 模型自由度 | Sam 的部分媒体流程要求指定第三方端点；部分扩展只支持固定 Provider | 用户自定义 Base URL、API Key、模型名和 API 模式 | 统一 Provider Adapter，Chat Completions 与 Responses 分离适配 |
| 网页与媒体 | `steipete/summarize` 已覆盖 URL、网页、字幕、媒体和扩展 | 复用其可验证思路，并增加桌面任务库、国内平台路由与权限体验 | 通用正文、平台适配器、字幕、转写按优先级调度 |
| 本地历史 | 单次浏览器扩展往往只显示当前结果 | 原文、结果、模型、提取方式和错误证据都可本地检索 | SQLite 保存任务、内容快照和执行记录 |
| Cookie 边界 | `cookies.txt` 或 `--cookies-from-browser` 可能覆盖全部站点 | 默认不读取 Cookie；需要时只申请当前域名、可撤销、短时使用 | MV3 optional permissions + 域名授权记录 + 内存级 Cookie Jar |
| 失败解释 | 常见产品只提示“抓取失败”或“无法总结” | 区分内容为空、需登录、平台变化、模型鉴权、限流、TLS 和超时 | 统一错误码、执行步骤时间线和下一步恢复操作 |

### 1.2 三类用户画像

#### 用户 A：跨平台重度阅读者

- 角色：每天阅读 X、YouTube、微信公众号、小红书和普通网页的个人用户。
- 核心目标：快速判断内容是否值得深入阅读，并获得可信的中文总结。
- 对现有工具最大的不满：登录页面抓不到、模型受限、失败原因不清楚。
- 切换触发功能：在已登录页面点击扩展即可把“眼前内容”送入桌面端。

#### 用户 B：内容研究与创作者

- 角色：需要整理选题、案例、视频字幕和多平台素材的研究者或创作者。
- 核心目标：保存来源、正文、摘要和翻译，随后导出到 Markdown 知识库。
- 对现有工具最大的不满：结果与来源分离，无法复核，也难以批量归档。
- 切换触发功能：每条结果附带提取方式、原文快照、来源链接和可移植导出。

#### 用户 C：重视隐私的 BYOK 用户

- 角色：拥有 DeepInfra、OpenRouter、OpenAI-compatible 网关、Ollama 等模型资源的技术型用户。
- 核心目标：使用自己的额度和端点，不把历史与 Cookie 上传到产品服务器。
- 对现有工具最大的不满：必须注册、必须购买内置额度或被绑定到单一 API。
- 切换触发功能：本地保存配置、任意兼容端点、清晰显示数据流向。

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |

| 普通网页和微信公众号的正文提取；可用 Readability 与站点适配器 | 承诺“任何链接 100% 成功”；动态平台与反爬规则持续变化 |
| YouTube、B站、X、抖音、小红书的公开字幕或媒体提取；二期引入 | P0 批量抓取账号主页、评论、关注列表或推荐流；会放大合规和维护风险 |
| 自定义 OpenAI-compatible 端点；本地 Ollama 作为后续适配 | P0 自建模型推理云、训练模型或代理所有用户模型流量 |
| macOS-first 桌面 APP 与 Chrome/Brave/Edge 扩展 | Safari 扩展、iOS、Android 不进入一期；机制与审核链路不同 |
| 本地历史、Markdown/TXT/JSON 导出 | P0 团队协作、公开分享链接和云端多用户权限 |
| 用户主动授权当前域名 Cookie；二期实现 | 默认扫描或导入整个 Chrome Cookie 数据库 |
| 本地免登录使用；注册后启用设备、权益、选择性加密同步和托管额度 | 用账号锁住本地历史，或因 Cloud API 故障禁止打开本地内容 |
| 全球优先的账号与隐私边界；macOS 先行、Windows 共享核心后续接入 | 第一天同时建设中国大陆与全球双云、双支付和双合规栈 |
| 10 万/100 万注册容量压测、恢复演练和成本护栏 | 在没有真实 MAU、DAU、RPS 和成本数据时提前部署微服务或多区域双活 |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| P0 必须完成“浏览器当前页 → 桌面 APP → 提取 → 总结/翻译 → 本地保存” | macOS-first，Electron + React + TypeScript | 视觉风格、品牌、动效、图标和排版系统 |
| 模型不得绑定单一端点；凭据不得进入仓库和普通日志 | P0 先支持 OpenAI-compatible Chat Completions，P1 加 Responses | 模型预设、提示词模板和输出风格 |
| Cookie 默认关闭，必须按当前域名主动授权、可撤销、短时使用 | P0 不实现 Cookie，优先 DOM；P1/P2 再按真实平台需求加入 | 授权弹窗文案、授权状态展示和撤销入口样式 |
| 提取失败必须展示阶段和恢复动作 | 统一 `category/code/retryable/action` 错误结构 | 技术详情折叠层级和诊断视图表现 |
| 用户原文和历史可导出、可删除 | SQLite 本地数据库，Markdown 为主导出格式 | 标签、收藏、搜索排序和结果卡片布局 |
| 第三方代码必须经过许可证检查 | 优先 MIT、Apache-2.0、BSD、Unlicense 源码依赖 | 可自行实现 GPL 项目中的产品思路，但不得复制受限代码 |
| 云端故障不得阻止本地提取、BYOK、历史和导出 | 本地免登录；注册用于同步、托管额度和设备权益 | 注册引导的时机、文案和奖励方式 |
| 原文和结果默认不上云；主动同步时客户端加密后上传 | 设置与同步索引可上云，正文以加密 blob 存储 | 同步筛选、冲突处理与恢复提示的视觉形式 |
| 跨扩展、进程和网络消息版本化；写请求幂等；数据库只向前迁移 | API v1 + `version/requestId/idempotencyKey` | 具体 ID 格式、错误详情折叠和诊断界面 |
| 100 万注册准备度不改变 TypeScript 主干和领域语义 | Fastify 模块化单体；按测量信号拆服务 | 部署厂商、缓存、队列、对象存储和观测后端 |

### 第 3.1 节 链接导入与任务创建

#### a) ASCII 图

```text
+----------------------------------------------------------------+
| 粘贴链接                                                        |
| https://mp.weixin.qq.com/s/example                              |
| 〈自动识别：微信公众号文章〉                                    |
|                                                                |
| 动作  (●) 总结   ( ) 翻译   ( ) 仅提取                         |
| 语言  自动匹配来源  v        模型  默认模型 v                    |
|                                      〈取消〉〈开始处理〉         |
+----------------------------------------------------------------+

空状态：粘贴一个网页、视频或文章链接，或从浏览器扩展发送当前页面。
错误状态：这不是可处理的 URL；可改为“粘贴原文”。
```

#### b) 交互流程

```text
粘贴 URL -> 规范化 URL -> 去重检查 -> 创建任务 -> 进入提取
                  |            |
                  |            +-- 已存在且已完成 -> 打开旧任务 / 重新运行
                  +-- 非 http(s) 或为空 -> 阻止提交并聚焦输入框

创建任务 -> 数据库不可写 -> 保留输入，提示选择可写数据目录后重试
创建任务 -> 桌面端离线但当前动作需网络 -> 建立待处理任务，显示“等待网络”
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| 空闲 | 未输入内容 | 输入框与示例说明 | 输入 URL 或收到扩展消息 |
| 校验中 | 用户提交 | 输入框右侧轻量进度 | URL 有效或返回校验错误 |
| 重复确认 | 数据库已有同一规范化 URL | 对话框显示旧任务时间 | 打开旧任务或确认新建 |
| 已排队 | 任务已创建、等待执行器 | 侧栏灰色圆点 | 执行器开始提取 |
| 阻塞 | URL 无效、数据目录不可写 | 红色内联提示 | 用户修正输入或权限 |

#### d) 依赖关系

读取：剪贴板、扩展消息、默认动作与模型设置。写入：`Task`、规范化 URL、初始 `Run`。输出给：提取路由器。

#### e) 待决问题

- 此处未解决：P0 是否允许一次粘贴多个 URL；安全默认是单条，批量进入 P2。
- 此处未解决：同一 URL 不同登录账号看到不同内容时，是否视为同一任务；默认允许建立新快照。

#### b) 交互流程

```text

              |                    |
              |                    +-- Readability 为空 -> 使用站点适配器/可见文本降级
              +-- 用户拒绝权限 -> 保留 URL，提示可复制链接到桌面端

```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| 未连接 | Native Host 不可用 | 灰点与“连接桌面 APP” | APP 启动并握手成功 |
| 可捕获 | 当前页允许注入且 APP 在线 | 绿点、动作按钮可用 | 页面切换或权限收回 |
| 捕获中 | 用户点击动作 | 分阶段进度：读取/清理/发送 | 成功或失败 |
| 内容过少 | 提取文本低于 200 字 | 黄色提示与三种恢复方式 | 切换范围、等待加载或重新捕获 |
| 受限页面 | 浏览器禁止注入 | 锁图标 | 用户切换到普通网页 |
| 已发送 | APP 返回任务 ID | 成功状态与“打开任务” | 关闭面板或继续操作 |

#### d) 依赖关系

读取：当前 Tab、DOM、选区、页面元数据和可选站点权限。写入：版本化 `CaptureEnvelope`。输出给：Native Messaging Host 和桌面任务入口。

- 此处未解决：Chrome Web Store 是否接受首次版本申请 `all_urls`；默认只用 `activeTab`，自动模式延后。
- 此处未解决：是否在 P1 支持页面截图与 OCR；默认不进入 P0。

#### b) 交互流程

```text
输入 -> 类型识别
  |
  +-- CaptureEnvelope 有正文 -> DOM 清理 -> 质量评分 -> 成功
  |
  +-- 公开文章 URL ----------> HTTP 获取 -> Readability -> 成功
  |
  +-- 支持媒体 --------------> 字幕 -> 媒体提取 -> Whisper -> 成功
  |
  +-- 登录受限 --------------> 要求浏览器打开；二期询问当前域 Cookie

媒体提取超时 -> 取消子进程 -> 保留已有元数据 -> 提示稍后重试或仅总结可见文案
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |

| 排队 | worker 尚未领取 | 队列位置/预计等待 | 开始执行或取消 |
| 运行中 | Provider 已接受 | 流式结果与停止按钮 | 成功、失败或取消 |
| 已退款 | 失败未产出有效结果 | 退款流水和原因 | 状态归档 |
| 托管暂停 | 预算、故障或维护 | 明确原因与 BYOK CTA | 服务恢复 |

#### d) 依赖关系

读取：`Entitlement`、任务正文、模型选择和全局 Provider 状态。写入：`ManagedJob`、只追加 `UsageLedger`、脱敏诊断和结果状态。输出给：桌面 Run/Artifact 与用量页面。

#### e) 待决问题

- 此处未解决：首批托管 Provider、模型和定价单位；接入前按全球可用性、成本和数据条款核对。
- 此处未解决：模型失败到什么程度算“有效产出并结算”；默认只有生成可保存 Artifact 才结算。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 “我眼前看到什么，就处理什么”

1. **竞品为何没有这个功能**：基于公开架构的推断，URL 总结产品通常由云端抓取器处理链接，天然拿不到用户浏览器内的登录态和渲染后 DOM；纯扩展又往往缺少媒体与本地任务能力。
2. **本产品如何实现**：扩展优先发送当前页面清理后的正文；只有正文不足时才退回 URL、平台适配器、字幕或用户授权路径。
3. **交互流程**：

```text
打开已登录页面 -> 点击 LinkDigest -> 预览“正文 6,240 字” -> 总结
                                      |
                                      +-- 内容不足 -> 告知原因并列出下一条提取路径
```

4. **风险与应对**：SPA、Shadow DOM、虚拟滚动可能导致正文不全；提供字数预览、选区发送、等待加载后重试和站点适配器，绝不暗示完整性已保证。

### 第 4.2 节 提取证据与失败阶梯

1. **竞品为何没有这个功能**：基于实际体验的推断，很多产品把抓取和模型调用合并成单一黑盒，错误卡片无法说明真正失败在哪一层。
2. **本产品如何实现**：每次运行保存不含秘密的步骤、耗时、输入来源、字数、降级路径和错误类别。
3. **交互流程**：

```text
任务失败 -> 展开执行记录
          +-- 当前 DOM：内容过少
          +-- URL 抓取：需要登录
          +-- 恢复建议：打开完整正文后重新点击扩展
```

4. **风险与应对**：技术信息过多会吓到普通用户；默认只显示一句人话和一个恢复按钮，技术详情折叠展示。

### 第 4.3 节 Provider-neutral 模型连接

1. **竞品为何没有这个功能**：固定端点能降低产品支持成本并绑定商业计费，但会造成模型不可用、地区受限和成本不透明。
2. **本产品如何实现**：把协议、Base URL、凭据、模型名和模型能力拆开；Provider Adapter 只负责协议翻译，不决定产品流程。
3. **交互流程**：

```text
添加模型 -> 选择 API 模式 -> 测试连接 -> 保存 -> 任意任务选择该模型
                                |
                                +-- 404/405 -> 建议切换协议或修正 URL
```

4. **风险与应对**：兼容端点并不完全兼容；建立合约测试，未知字段宽容读取，错误响应原样保留脱敏摘要。

### 第 4.4 节 “先获得价值，再决定是否注册”

1. **竞品为何没有这个功能**：基于商业模式的推断，依赖云端推理、同步或订阅的产品通常需要先识别用户并控制成本，因此把账号放在首次价值之前。
2. **本产品如何实现**：本地核心不依赖 User；账号只在设备、同步、托管额度和付费权益出现时介入。退出登录不删除或锁住本地历史。
3. **交互流程**：

```text
安装 APP -> 不注册处理第一条链接 -> 保存本地历史
                                      |
                                      +-- 需要跨设备/托管额度 -> 主动注册
                                      +-- 不需要 ------------> 永久本地模式
```

4. **风险与应对**：免登录会降低早期注册率可见性；使用“首条成功任务、7 日本地留存、主动注册转化”分别衡量价值与增长，不用强制账号制造虚假注册。

### 第 4.5 节 用户可验证的数据边界

1. **竞品为何没有这个功能**：基于云端产品架构的推断，服务端需要处理明文内容时，很难向用户承诺“服务器看不到原文”；许多产品也不会展示同步对象和密钥状态。
2. **本产品如何实现**：设置页明确区分本地、账号 metadata、加密 blob 和托管模型发送路径；内容同步由客户端加密，BYOK 直接连接用户 Provider。
3. **交互流程**：

```text
打开“数据去向” -> 查看本地/同步/托管三条路径
                  +-- 关闭内容同步 -> 原文仅本地
                  +-- 开启内容同步 -> 客户端加密后上传
                  +-- 使用托管模型 -> 单任务确认发送范围
```

4. **风险与应对**：端到端加密可能因密钥丢失导致无法恢复；实施前完成威胁模型和恢复设计，UI 不承诺尚未验证的“零知识”能力。

### 第 4.6 节 超预期机会

- **来源可信度卡**：结果顶部明确标记“完整正文 / 当前可见正文 / 字幕 / 音频转写 / 仅文案”，帮助用户判断可依赖程度。
- **一键更好结果**：保留同一正文，用另一个模型或不同长度重新生成，并提供并排比较；不进入 P0。
- **失败也有产物**：模型失败时仍可保存和导出已经提取的原文，抓取失败时仍保留链接与诊断。
- **学习模式**：开发版可将一次任务的数据流可视化，让 Syc 看到扩展、APP、提取器和模型如何交接；正式版默认关闭。
- **本地模式徽章**：始终显示“此任务未经过 LinkDigest 云端”或“已发送到托管模型”，让隐私不是隐藏设置。

## 第六章：技术架构

完整架构边界以 `docs/ARCHITECTURE.md` 为真相源，容量公式、SLO 和扩容触发条件以 `docs/CAPACITY_MODEL.md` 为真相源。本章只保留会改变产品行为和实施顺序的架构摘要。

### 6.1 四层架构

```text
+--------------------------------------------------------------------------------+
| Chromium Extension：当前页 DOM/选区、最小权限、CaptureEnvelopeV1               |
+-----------------------------------+--------------------------------------------+
                                    | Native Messaging
+-----------------------------------v--------------------------------------------+
| Electron Local Core：Main / Preload / Renderer / Utility Process              |
| Extraction | BYOK Provider | SQLite | Keychain | Export | Optional Cloud Client|
+--------------------------+-----------------------------+-----------------------+
                           | 本地默认                    | 用户主动启用 API v1
                           v                             v
                SQLite / OS Keychain      TypeScript Fastify Modular Monolith
                                          Identity | Entitlement | Sync
                                          Managed AI | Usage Ledger | Remote Config
                                                        |
                                                        v
                                          PostgreSQL / Encrypted Object Storage
                                          Replaceable Cache / Queue / Workers
```

本地核心始终是完整产品；云端是账号和增值能力控制面。API 与 worker 使用同一 TypeScript 代码库、不同进程入口。PostgreSQL 保存云端唯一事实；缓存、队列和对象存储可以替换，不允许保存无法重建的唯一业务状态。

| OpenTelemetry | Node API/worker traces 与 metrics | 观测语义与后端厂商解耦 | 未知 |
| Queue adapter | 托管模型、同步、删除与 outbox 调度 | 吸收突发并允许替换具体队列实现 | 具体实现待云端阶段决定 |
| `yt-dlp` | 二期多平台字幕和媒体解析 | 当前公开提取器包含 YouTube、X/Twitter、Bilibili、Douyin、XiaoHongShu | 源码与不同发布二进制许可证/体积需打包前复核 |
| `ffmpeg` | 二期音视频转码与音频提取 | 平台成熟且与 `yt-dlp` 协同广泛 | 未知；许可证取决于具体构建 |
| Whisper 兼容运行时 | 无字幕媒体转写 | 可在本地和云端提供可替换后端 | 模型与运行时体积未知，二期实测 |

最大客户端风险是 Electron、SQLite binding、Native Messaging、签名、公证和自动更新组合尚未完成 release spike；最大云端风险是把“百万注册”误解为第一天拆微服务。应对方式是先验证最薄本地链路和发布链路，再用模块化单体按 `CAPACITY_MODEL.md` 压测；只有资源曲线、故障隔离或团队边界出现真实证据时才拆服务。

### 可替换技术原则

推荐 Electron + React + WXT 与 Fastify TypeScript modular monolith。Electron shell、WXT、身份提供商、队列、对象存储和观测厂商都可在验证失败时替换。不可变的是：扩展/桌面/云端进程隔离、版本化协议、领域模型、秘密不进普通存储、本地核心免登录、正文默认不上云、写请求幂等、数据库只向前迁移。

100 万注册准备度使用 1,000 RPS 短时突发、100 jobs/s 入口、100 万用户记录和 1 亿条同步 metadata 进行验证；这些是测试上限，不是现在购买服务器或部署多区域的指令。

### 7.5 加载状态

- 小于 `200ms` 的本地操作不显示 Spinner，避免闪烁。
- `200ms–2s` 的正文清理使用按钮内进度和当前步骤文字。
- 超过 `2s` 的网络、字幕和模型操作显示任务级步骤、停止按钮和已耗时。
- 超过 `10s` 仍未收到模型首个 Token，显示“仍在等待模型”，但不自动判定失败。
- 媒体下载和转写必须分别显示字节或时长进度；无法获得总量时显示已处理时长。
- 账号和权益检查超过 `500ms` 时显示局部云状态，不遮挡本地工作区。
- 同步排队显示待处理数量和最后成功时间；托管任务分别显示“已预留额度、排队、运行、结算/退款”。

## 第八章：导出与输出系统

### 8.1 支持的输出格式

| 格式 | 使用场景 | 质量选项 | 备注 |
|---|---|---|---|
| Markdown | Obsidian、Git、知识库和长期保存 | 结果；原文+结果；含执行证据 | P0 主格式 |
| TXT | 纯文本复制和通用兼容 | 结果；原文+结果 | P0 |
| JSON | 数据迁移、调试和未来导入 | 完整任务；脱敏任务 | P0，不包含凭据/Cookie |
| HTML | 保留阅读排版并浏览器打开 | 单文件 | P1 |
| PDF | 分享和打印 | A4/Letter、浅色/深色 | P2 |

### 8.2 输出文件结构

```text
LinkDigest-浏览器扩展与本地AI-2026-07-13/
├── result.md
├── source.md
├── metadata.json
└── media/
    ├── cover.webp
    └── transcript.vtt
```

`metadata.json` 包含来源 URL、标题、作者、提取方法、完整性标记、模型名和时间，不包含 API Key、Cookie、Token、完整请求 Header 或本机绝对敏感路径。

### 8.3 批量处理流程

```text
选择多个任务
    |
    v
读取本地结果（可并行，最大 4）
    |
    +-- 单项缺少结果 -> 询问跳过或仅导出原文
    |
    v
生成各任务目录（可并行，最大 4）
    |
    v
生成批次 index.md（串行，保持排序）
    |
    v
可选压缩 ZIP（串行） -> 显示保存位置与失败项
```

P0 只实现单项导出；批量导出进入 P2。任何失败不得删除已成功生成的文件。

### 8.4 账号与云端数据导出

账号数据导出与本地内容导出分开：

- 账号导出包含 User、Device、Entitlement、SyncManifest、UsageLedger 和删除状态。
- 加密 blob 可以下载原始密文；可读原文与结果必须由持有密钥的客户端解密后导出。
- 导出不包含 session、Identity Provider token、API Key、Cookie、内部风控字段或其它用户数据。
- 删除账号不自动删除本机 SQLite；用户可以在删除前完成本地 JSON/Markdown 导出。

## 第十一章：开发者交接说明

### a) 实现顺序建议

你先不要做漂亮首页、账号服务或 `yt-dlp`。第一步建立 pnpm TypeScript monorepo、版本锁定和自动检查；第二步实现 `CaptureEnvelopeV1`、`Task`、`ContentSnapshot`、`Run`、`Artifact`、`AppError` 及兼容测试；第三步跑通测试文章 → 扩展 service worker → Native Messaging → Electron 安全 IPC → 最薄窗口；第四步加入 SQLite 和迁移；第五步接 BYOK Provider。只有本地闭环与 release spike 有证据后，才建立 Fastify API/worker 骨架，再接账号、选择性加密同步和托管额度。

### b) 最可能导致返工的三个决策

1. **本地核心是否依赖账号或云端**
   - 安全默认：完全不依赖；账号只提供设备、权益、同步和托管能力。
   - 改变信号：无。它是产品硬约束；商业需求只能改变增值入口，不能锁住本地数据。
2. **模块化单体何时拆服务**
   - 安全默认：Fastify modular monolith，API/worker 分进程并横向扩展。
   - 改变信号：独立资源曲线、故障隔离、团队所有权或 profiling 证明的局部瓶颈；注册数字本身不是信号。
3. **选择性加密同步如何实现**
   - 安全默认：原文默认本地，主动选择后客户端加密上传；服务端只存 metadata 与 ciphertext。
   - 改变信号：安全威胁模型、恢复体验或审计库验证失败时，推迟内容同步，不允许降级为静默明文上传。

### c) 哪里要严格，哪里可以灵活

- 第一章约束分层：**约束**。本地免登录、隐私、Provider-neutral 和 P0 闭环不能重新解释。
- 第二章布局：**建议**。可以改视觉比例，但必须保留任务列表、原文/结果/执行记录。
- 第三章流程和失败路径：**约束**。可以换组件，但不得合并错误层或跳过恢复操作。
- 第四章视觉表现：**建议**。可信度卡和失败阶梯的语义必须保留，呈现方式可优化。
- 第五章数据语义：**约束**。实现可用关系表，但本地任务对象、云端账号对象、加密 blob 和用量流水必须分离。
- 第六章具体框架：框架为**建议**，边界为**约束**。Electron、WXT、Fastify 和云厂商可替换；TypeScript 主干、跨端隔离、版本化、本地核心与只向前迁移不可变。
- 第七与第八章：**建议**。遵循平台规范时可调整快捷键和导出 UI。
- 第九与第十章：**约束**。不得把 P2 偷塞进 P0，也不得在没有测量证据时宣称达标。

### d) 已知的未知项

- 此处未解决：正式产品名、商标、域名和视觉品牌。
- 已确认：全球优先、商业闭源、macOS 先行，Windows 共享核心在 P2 验证。
- 此处未解决：macOS 最终走公证 DMG、Mac App Store 或两者；Native Messaging 与沙盒能力需实测。

### e) 验收剧本

验收剧本 1：在未注册账号、Cloud API 被阻断的 macOS 上，用 Chrome 打开公开文章并点击 LinkDigest，应在桌面 APP 800ms 内看到新任务，完成 BYOK 总结、本地保存和 Markdown 导出，并用网络记录证明没有调用 LinkDigest 云端。

验收剧本 2：在 Chrome 已登录的 X 页面打开一篇 Article，点击扩展后应优先发送已渲染正文；断开 URL 抓取网络仍保留 DOM 快照，并用扩展消息和 SQLite 记录证明没有读取整个 Cookie 数据库。

验收剧本 3：配置一个自定义 OpenAI-compatible Base URL、错误模型名和无效 Key，测试连接分别显示协议/模型或 401 类错误；日志和导出不得包含完整 Key，并用 Keychain 引用与敏感词扫描验证。

验收剧本 4：注册测试账号并只开启“同步摘要”，应在本机生成密文，云端 PostgreSQL 只出现 manifest/blob metadata，对象存储只出现 ciphertext；制造版本冲突后保留两份并提供选择，不覆盖本地原文。

验收剧本 5：对同一托管请求重放相同 `idempotencyKey` 10,000 次，应只生成一个 ManagedJob 和一次额度预留；模拟 Provider 失败后追加退款流水。随后以 1,000 RPS 突发 15 分钟运行控制面压测，API p95 ≤ 300ms、无重复扣费，并用 traces、metrics 和 ledger 对账验证。

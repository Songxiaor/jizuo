# V0.1 Vertical Slice：当前页面进入 macOS APP

> 状态：自动化实现与本机进程链路已通过；Chrome、Brave 150 与 Edge 150 隔离 Profile 的真实证据已记录。Edge 证据分为 Popup 人工预览观察，以及修复后 Service Worker → Native Host → Unix socket → Swift App 的 20/20 传输；没有把它们伪装成一次连续工具栏点击截图。本文只定义第一条可运行链路，不代表完整 P0。

## 1. 场景

用户在 Chromium 浏览器打开仓库提供的固定测试文章，点击 LinkDigest 扩展。扩展读取正文，通过 Native Messaging 发送给本机 LinkDigest，SwiftUI 主窗口显示标题、URL、正文、字符数与捕获方式。

这个阶段不调用模型、不写 SQLite、不设计正式视觉品牌。目标是证明 Swift 与 TypeScript 之间最危险的交接可以稳定工作。

## 2. 角色与交接

| 角色 | 职责 | 交接物 |
|---|---|---|
| Test Fixture | 提供稳定、无登录、可断言的文章页面 | 已知标题、正文和字符数范围 |
| Content Script | 从当前页面读取候选正文 | 页面元数据与正文候选 |
| Extension Service Worker | 校验权限和载荷，调用 Native Messaging | `CaptureEnvelopeV1` JSON |
| Native Host | 通过 stdin/stdout 读写 Chrome framing 消息 | 已校验消息或结构化错误 |
| macOS APP | 接收消息并更新当前任务状态 | Swift 领域对象 |
| SwiftUI View | 展示来源、正文和连接状态 | 用户可观察结果 |

## 3. 新名词

- **Content Script**：运行在网页上下文附近、负责读取 DOM 的扩展脚本；它不能直接调用 Native Messaging。
- **Service Worker**：扩展后台协调者，负责权限、消息校验和与 Native Host 通信。
- **Native Messaging**：Chromium 扩展与本机程序通过标准输入输出交换长度前缀 JSON 的机制。
- **CaptureEnvelopeV1**：扩展交给 APP 的第一版稳定消息合同。
- **Release spike**：用最薄实现验证高风险技术组合，而不是先建设完整产品。

## 4. 消息最小字段

```jsonc
{
  "version": 1,
  "requestId": "request-id",
  "createdAt": "ISO-8601",
  "source": {
    "kind": "browser_capture",
    "url": "https://example.test/article",
    "title": "Test Article",
    "platform": "generic"
  },
  "capture": {
    "method": "rendered_dom",
    "text": "Readable content",
    "characterCount": 16,
    "completeness": "full_article",
    "capturedAt": "ISO-8601"
  },
  "evidence": {
    "sourceLabel": "Current page DOM",
    "usedCookie": false
  }
}
```

`contracts/capture-envelope-v1.schema.json` 是 TypeScript 与 Swift 共同使用的语言中立合同来源。TypeScript 使用 Ajv 在构建期生成静态 validator，Swift 使用 bundled schema validator 执行同一份 Schema；两端再用共同 fixtures 验证无法仅靠类型声明保证的规则。TypeScript interface 不能单独充当跨语言真相源。

## 5. APP 已运行成功路径与 APP 未运行恢复路径

### 5.1 APP 已运行成功路径

```text
打开固定测试页
  → 点击扩展
  → 显示检测到的标题和字符数
  → 点击“发送到 LinkDigest”
  → 已运行的 APP 直接接收
  → Swift 校验 version 和必填字段
  → 主窗口显示正文
  → 扩展收到 taskAccepted 响应
```

### 5.2 APP 未运行恢复路径

Host 不自动启动 APP，也不暂存正文。APP 未运行时返回 `APP_UNAVAILABLE / open_app`；用户手动打开 APP 后，从当前页面重新发送。

## 6. 必测失败路径

| 场景 | 期望错误 | 用户恢复动作 |
|---|---|---|
| Native Host 未安装 | `NATIVE_HOST_NOT_FOUND` | 打开安装说明或重新检测 |
| APP 未运行（Host 不负责唤起） | `APP_UNAVAILABLE / open_app` | 手动打开 APP 后重试 |
| 收到 `version: 2` | `PROTOCOL_VERSION_UNSUPPORTED` | 升级扩展或 APP |
| 正文为空 | `CAPTURE_CONTENT_EMPTY` | 等待页面加载或选择文字 |
| 字符数与正文不一致 | `CAPTURE_COUNT_MISMATCH` | 扩展重新构建载荷 |
| 消息超过上限 | `CAPTURE_PAYLOAD_TOO_LARGE` | 截断并标记，或拒绝发送 |
| URL 不是 http/https | `CAPTURE_URL_UNSUPPORTED` | 切换到普通网页 |
| 响应超时 | `NATIVE_MESSAGE_TIMEOUT` | 保留页面状态并允许重试 |

错误日志不得包含正文全文、Cookie、Token、API Key 或完整私人 URL。

## 7. 验收标准

- Chrome、Brave、Edge 均有固定测试页链路证据；Edge 的 Popup 预览观察与修复后 Service Worker 20/20 传输分开记录，修复后未再次要求 Syc 做工具栏点击。
- APP 已运行成功路径与 APP 未运行恢复路径都留下证据；不把恢复路径描述为 Host 自动冷启动 APP。
- Swift 与 TypeScript 对同一个有效 fixture 均校验通过。
- 两端都拒绝不支持的 major version。
- 两端都拒绝字符数不一致和非 Web URL。
- 20 次连续发送不丢失、不重复创建、不崩溃。
- 从 service worker 发出到 SwiftUI 显示，Release 构建 p95 ≤ 1 秒。
- Native Host 不存在时不出现无限重试。
- `./scripts/doctor` 与适用测试全绿。

## 8. 停止条件

出现以下任一情况时停止扩展功能开发，先解决 release spike：

- Native Host 无法形成可复现的安装与卸载流程。
- 公证构建无法定位或启动 Native Host。
- Swift 与 TypeScript 协议需要手工维护且无法建立一致性测试。
- 扩展必须申请超出 `activeTab` 的广泛权限才能完成固定场景。

停止不代表改回 Electron。应先记录证据，再比较原生 Helper、安装包结构或其它受控方案。

## 9. Native Messaging 查找根与回滚

Edge 使用隔离启动参数 `--user-data-dir=/tmp/...` 时，Native Messaging 用户级 manifest 查找根随之变为 `<user-data-dir>/NativeMessagingHosts/`。默认 Edge 启动仍使用 `~/Library/Application Support/Microsoft Edge/NativeMessagingHosts/`。安装脚本以 `--browser edge --user-data-dir /absolute/profile` 显式选择隔离目标；Chrome、Brave 不接受该参数。Profile 必须是词法规范的现存非根绝对目录，从 `/` 到 Profile 的任一 symlink 组件都会被拒绝，目标严格为直接 `NativeMessagingHosts` 子目录。先 dry-run 看 `TARGET`，再按需 `--apply` 写入；创建后与写入前会复验，但不把这种用户态检查描述成彻底消除并发换链。

回滚默认 Edge 目标时，可运行只读的 `scripts/native-host/uninstall-plan.sh --browser edge` 核对计划；该脚本目前不接受 `--user-data-dir`。隔离 Profile 应以安装 dry-run/apply 打印的 `TARGET` 为准，在对应 `<user-data-dir>/NativeMessagingHosts/` 人工核对，再恢复同 basename 的时间戳 `.bak` 或删除测试 manifest。脚本不自动删除、移动或恢复；默认路径和隔离路径分别回滚，避免误改另一份 manifest。

## 10. 回滚

本阶段不迁移用户数据。若路线验证失败，可删除尚未发布的 V0.1 壳代码并保留：

- 协议规范与 fixtures。
- 测试结果和失败证据。
- Project Brain 中的 reversal 记录。
- 产品 PRD 的 local-first、当前页面优先和 Provider-neutral 边界。

任何路线变更必须先更新 Brain 决策，再同步 PRD 与 Architecture。

## 2. 错误与恢复语义

- 22 个当前 stable code 都通过同一个 App 层错误目录取得 `message` 与 `recoveryAction`，SwiftUI 不直接展示内部 code 或未知输入。
- 401 提示更新 API Key；429 提示稍后重试或更换模型服务；5xx 提示 Provider 暂时不可用并稍后重试。
- 协议不兼容提示检查 Base URL 是否为 OpenAI-compatible Chat Completions API root。
- 没有 partial 的失败进入 `failed`；已有 partial 的失败进入 `incomplete` 并明确显示“结果不完整”。
- 用户停止显示“用户已停止，结果不完整”，并继续保留已产生的部分文本。
- 未配置、没有 capture、空正文、配置存取和 Keychain 失败都有下一步动作。

## 3. Secret hygiene 证据

- API Key 持久化只进入 Keychain；ProviderProfile 和 UserDefaults 只保存非敏感字段与 opaque reference。
- API Key 只在 `loadCredentials → ModelRunOrchestrator → ModelProvider.stream` 的局部请求生命周期内短时存在。
- fake server 与 fake provider 只记录 Authorization 是否存在/匹配或 Key 是否存在，不保存 header value。
- `ModelProviderFailure.description` 只输出 stable code；用户文案不接受 Provider 原始 body、Header、完整 URL 或 `safeDetail`。
- Orchestrator 在 delta 进入 RunState 前对本次 API Key 做精确 redaction；测试覆盖成功结果和 incomplete partial 两条路径。
- 随机 sentinel 测试覆盖 RunState description、ViewModel 可见文本、用户错误文案、fake records、ProviderProfile 编码和 UserDefaults 原始数据。
- `pnpm secret:check` 静态检查高置信 secret、生产日志中的 secret/header/body 可疑形状、`@Published`/`@Observable` 与 RunState 的 secret-shaped 字段、fixture/snapshot、未知 code 的可见 UI sink 和 UserDefaults adapter；命中时只打印规则名与路径，不打印疑似值。`sentinel-<UUID>` 和 `not-a-real-key` 这类明显测试标记不会被当成真实 Key pattern。

## 6. 当前限制与恢复

- 没有真实 Provider 抽样；如需验证 1–2 个真实端点，必须由 Syc 单独授权，并使用专用测试 Key 与非私人正文。
- 旧 Keychain item 删除仍是 staged save 完成后的 best-effort；删除失败可能留下 orphan，但不会让新 profile 指向不存在的 secret。清理队列或维护入口留给后续维护任务。
- 翻译目标语言当前固定为简体中文；V0.2 没有目标语言选择控件。
- 数字形式 `Retry-After` 已限制最多 10 秒；HTTP-date 当前回退到可注入 backoff。
- Edge 未完成时，V0.2 工程证据不能被用来宣称 V0.1 浏览器矩阵完整。
- 单独连接测试 UI 若后续实现，必须由 Application service 短时读取 Key，不得让 SwiftUI ViewModel 直接访问 Keychain 或持有完整 Key。
- 当前 `/tmp` Host 路径只用于 V0.1 测试与本地进程交接，不是签名、公证或发布方案。

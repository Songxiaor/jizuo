## 线索核实 · 媒体本地化后路径被 `https://` 过滤？

主控提示：`cover_image=0` ≠ 无封面；`previewCoverURL` 回退 `firstMarkdownImageURL`，该解析器只接受 `https://`；`GRDBHistoryRepository` 把 `previewCoverURL` 传给列表。问：本地化后的正文图路径会不会被滤掉。

**结论：对当前用户库，不是根因。保持 `https://` 边界，不把任意本机路径放进封面解析。**

现场证据：

- 最新 snapshot 全部 markdown 图 905 条，**全部** `https://`。`file://` / 相对路径 / 裸本地路径 = 0。X 第一张 markdown 图：161 条 https，220 条无图，0 条非 https。
- `cover_image` 18 条 https；1 条微信 `http://mmbiz.qpic.cn/...`（图库层 `WeChatArticleLayout.coverURL` 会升 https，留给 R03）。
- HTML `<img src>` = 0。
- `HistoryViewModel.backfillRemoteImagesIfNeeded` 注释写明：补下载只刷新本地图片列表，**不改正文、不改库**。`GitHubREADMEImageCache.stageRemoteMarkdownImages` 按正文里的绝对 https URL 哈希落盘，详情再用同一 URL 反查。
- 记录 2 图文帖：正文仍是 `![](https://pbs.twimg.com/...)`，同时 `GitHubREADMEImages/bad8f0e2-…/` 有缓存，图库封面显示成功——说明「远程 URL 留在正文 + 平行缓存」这条链路是通的。
- 记录 3 视频帖：正文无任何 `![]()`，过滤器没有可滤的对象。

因此：若以后有人把正文改写成 `file://` 或相对路径，过滤器**会**丢掉封面；当前实现没有这样改写。本地图已经通过「https URL → 应用支持目录下的哈希文件」支持，不必放开任意本机文件。

代码：`firstMarkdownImageURL` 加了上述约束注释；测试 `testFirstMarkdownImageURLAdmitsHTTPSOnlyAndRejectsLocalPaths` 拒绝 `file://`、绝对本地路径、相对路径、`http://`，接受 `https://`。`source scripts/xcode-env.sh` 后 `swift test --filter …testFirstMarkdownImageURLAdmitsHTTPSOnlyAndRejectsLocalPaths` **1 passed**（本机默认 CommandLineTools 无 XCTest，未改全局 xcode-select）。

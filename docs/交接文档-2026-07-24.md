Syc 的迭代节奏是**边做边在本机看效果**，不要每次都做完整安装包，也**不要「模拟新机」验证**：

1. **改完一个功能/修复后，直接在 Syc 这台开发机上 `open` 打开 App 让他现场测**。开发机有 `.build`，`open <暂存>/LinkDigest.app` 直接能跑（§3.1 的跨机崩溃只在**别的**机器上发生，本机不受影响）。
   ```bash
   swift build --package-path apps/desktop -c release   # 或改扩展就 pnpm --filter @linkdigest/browser-extension build
   open <构建出的>/LinkDigest.app
   ```
2. **在本机根据 Syc 的现场反馈迭代**（尤其站点选择器：让他抓真实页面，把 DOM/og 结构告诉你再校准）。

> 一句话：**日常 = build → 本机 open → 现场测 → 迭代**；**收尾 = 打完整包**。别把「模拟新机」当常规验证。

## 3. 必读的坑

### 3.1 打包崩溃根因（`build_app_bundle` bug）
`release_unit.build_app_bundle`（`scripts/native-host/release_unit.py`）把 SwiftPM 资源包放进 `Contents/Resources/`，但生成的 `Bundle.module` 访问器（`.build/.../LinkDigestCore.build/DerivedSources/resource_bundle_accessor.swift`）只找两处：`Bundle.main.bundleURL/<name>.bundle`（对 .app 是**根目录**）和一条**编译时写死的本机 `.build` 绝对路径**。
- 结果：**app 只能在打包它的机器上跑**（靠 .build 兜底），换机崩 `could not load resource bundle`。这影响 `release/` 里所有 DMG（README 说「自动化从未启动过 App」，所以从没暴露）。
- 本会话的绕过：打包后把 `LinkDigest_LinkDigestCore.bundle` + `GRDB_GRDB.bundle` 拷到 `.app` 根目录再 ad-hoc 重签。**副作用**：`codesign --verify --strict` 报 "unsealed contents present in the bundle root"（ad-hoc 自测能跑，但不是可公证布局）。
- 正规修复方向：让 accessor 认 `Contents/Resources`（改成 Xcode app-target 构建，或加自定义资源解析），别把东西放根目录。

### 3.2 抽取逻辑有**两份拷贝**（最容易漏）
`src/content/extract.ts` 里：
- `extractCurrentPage`（+ `pickContentRoot`/`scrubNoise`/`NOISE_SELECTOR`）：**可测试版**，vitest 用。
- `extractPageInIsolatedWorld`（约 2120 行起）：**生产版**，通过 `chrome.scripting.executeScript({func})` 注入，**必须完全自包含**（不能引用模块级函数），内联了自己的一套 noise/content-root/各平台分支。
👉 **任何抽取/清洗/平台分支的改动，两份都要改**，否则测试过了但生产不生效（B站/小红书/A类我都改了两份）。

### 3.3 后台捕获门禁
`sendCapture`（background.ts）过去用 `isUnimplementedPlatformHost` 拦未适配平台。本会话已删除。新增平台若只想「识别不抓取」，注意别再引入类似门禁把它挡在提取器之前。

### 3.4 契约改动链
改平台枚举 = 改 `contracts/*.schema.json` → `pnpm generate:validator` → `scripts/sync-contracts.sh`。`check-contract-sync.sh` 会校验 Swift 副本一致；`pnpm check:validator` 校验 validator 与 schema 同步。

### 3.5 图标
- 历史侧栏图标：`apps/desktop/Assets/PlatformIcons/*.svg`（zhihu/medium/toutiao/bilibili/xiaohongshu/reddit/weibo/douban/juejin 已存在）；映射在 `PlatformIconCatalog.swift` 的 `assetTable`（host→svg）。

## 5. 打包流程（ad-hoc 本地测试版）

正规 local-test 发布管线锁定在旧冻结候选、打不了当前分支，用轻量路径：

```bash
# 1. 构建到暂存目录（别覆盖 ~/Applications 日常 App）
python3 scripts/build-and-deploy-local.py --replace \
  --app-destination <暂存>/LinkDigest.app \
  --extension-destination <暂存>/LinkDigest-extension-0.2.0

# 2. 资源包补到 .app 根目录（否则换机崩，见 §3.1）+ ad-hoc 重签
cp -R <暂存>/LinkDigest.app/Contents/Resources/LinkDigest_LinkDigestCore.bundle <暂存>/LinkDigest.app/
cp -R apps/desktop/.build/arm64-apple-macosx/release/GRDB_GRDB.bundle <暂存>/LinkDigest.app/
codesign --force --deep --sign - --identifier com.syc.linkdigest <暂存>/LinkDigest.app

# 3. 只改扩展时只重建扩展：pnpm --filter @linkdigest/browser-extension build

# 4. ditto 打 zip（保签名）
ditto -c -k --sequesterRsrc --keepParent <暂存目录> ~/Downloads/LinkDigest-<日期>.zip
```

**新机安装**：删旧 app → 解压拖进「应用程序」→ `xattr -cr /Applications/LinkDigest.app` → 打开。浏览器抓取需 App「浏览器支持」装 Host + 扩展页开发者模式加载扩展文件夹。详见 `docs/新机测试指南.md`。

# LinkDigest 学习协作指南

## 一句话

学习发生在 APP 被设计、实现和验证的当下：AI 负责把正在使用的概念讲清楚，不设置课后作业、考试或答题门槛；Syc 想深挖时再单独开小窗口。

## 1. 为什么要边做边讲

LinkDigest 同时是商业 APP 和完整开发学习工程。只交付代码，Syc 无法判断架构是否合理；先把所有知识学完再开发，又会让真实产品长期停工。因此采用下面的主流程：

```text
真实开发任务
   |
   v
AI 先解释当前场景和组件分工
   |
   v
AI 实施，并在交接点解释输入、输出和失败表现
   |
   v
自动化工程验证
   |
   +-- Syc 没有疑问 ------> 继续下一阶段
   |
   +-- 想快速澄清 -------> 当前对话补充人话解释
   |
   +-- 想系统深挖 -------> 单独开小窗口，不阻塞主开发
```

工程验证证明产物正确；过程讲解帮助 Syc理解为什么这样做。两者都由任务交付，不把证明“已经学会”的责任转给 Syc。

## 2. 每个任务怎么讲

### 开始前

按“场景 → 角色与交接 → 工作流 → 工具协同”说明：

1. 用户或系统遇到什么问题。
2. 这次只处理哪一段。
3. 哪些组件参与，各自只负责什么。
4. 上一步把什么交给下一步。
5. 最多 3–5 个本次真正需要的新名词。

### 实施中

阶段更新不能只说文件名、命令或完成百分比。每到一个组件边界，至少说明：

- 当前组件为什么存在。
- 它读取什么、写出什么。
- 为什么选择当前方向。
- 它坏掉时用户会看到什么。
- 下一阶段拿到的交接物是什么。

### 完成时

- 给出自动测试、检查或人工工程证据。
- 说明失败和恢复路径。
- 记录已经解释的概念和可选深挖入口。
- 可提供 5–15 分钟跟做动作，但明确它不阻塞继续开发。

## 3. 名词怎么解释

首次出现的核心名词回答五个问题：

1. 一句人话怎么说。
2. 像现实生活里的什么。
3. 位于 LinkDigest 哪一段。
4. 为什么当前任务需要它。
5. 没有它或它损坏时，用户看到什么。

### 讲解深度

| 等级 | 项目需要提供什么 | 适用对象 |
|---|---|---|
| L1 认识 | 给出人话定义，知道它大概解决什么 | 一次性命令、内部工具选项 |
| L2 定位 | 指出它在系统哪里、上下游和交接物 | 框架、模块和服务角色 |
| L3 共同观察验证 | 展示正常与失败证据，说明如何判断是否工作 | 扩展、API、数据库、同步、安全边界 |
| L4 修改 | 提供一处可控修改及影响范围 | Syc 主动想深入的模块 |

等级表示项目已经提供到什么深度，不是 Syc 的考试分数。核心架构默认讲到 L3；L4 是选修。

## 4. 五条 APP 学习主线

### 主线 A：产品与用户闭环

- 场景：为什么有人安装、第一次成功是什么；注册或付费只作为 P1+ 讨论，不进入当前免登录、无付费的 P0。
- 核心知识：用户画像、PRD、P0–P3、激活、留存、验收指标。
- 项目位置：`docs/PRD.md`、任务流程和产品数据。

### 主线 B：桌面端、扩展与进程隔离

- 场景：如何把浏览器当前页面安全交给本地 APP。
- 核心知识：Manifest V3、Content Script、Service Worker、Native Messaging、SwiftUI、AppKit bridge、Swift Concurrency。
- 项目位置：TypeScript 浏览器扩展、macOS 原生 APP 和语言中立协议。

### 主线 C：本地数据、API 与迁移

- 场景：如何保存历史并在版本升级后不丢数据。
- 核心知识：领域模型、JSON Schema、SQLite、Keychain、migration、取消和错误语义。
- 项目位置：跨语言合同、macOS 本地核心和安全存储。

### 主线 D：远期云端、容量与可观测性

- 场景：如何从公开测试增长到 10 万、100 万注册用户而不凭感觉扩容。
- 核心知识：模块化单体、RPS、队列、SLO、trace、metric、备份与恢复。
- 项目位置：`docs/CAPACITY_MODEL.md` 和未来阶段；不进入 P0。

### 主线 E：安全、测试、签名与发布

- 场景：如何把开发版变成用户敢安装、商店允许发布、出错可恢复的正式产品。
- 核心知识：Keychain、最小权限、secret scan、许可证、自动测试、代码签名、公证和更新。
- 项目位置：安全边界、CI、构建和发布流程。

## 5. 阶段课程随产品推进

| 阶段 | 产品交付 | 当场解释重点 |
|---|---|---|
| 路基 | macOS 原生架构、Project Brain、精简 PRD | 项目边界、记忆真相源、技术路线反转 |
| V0.1 交接 | 当前页 → 扩展 → Native Messaging → SwiftUI | 进程、跨语言协议、失败恢复 |
| P0 本地闭环 | 提取 → BYOK → SQLite → 导出 | Provider、数据库、Keychain、取消 |
| P1 增长入口 | 账号、设备、同步、托管额度 | Identity、加密、权益、计量 |
| P2 10 万准备度 | 限流、队列、灾备、诊断 | RPS、SLO、可观测性、恢复 |
| P3 100 万准备度 | 容量压测、归档、多区域评估 | 扩缩容、成本、拆服务触发条件 |
| 发布 | 签名、公证、扩展商店和隐私材料 | 供应链、安全审核、发布回滚 |

## 6. 小窗口深挖规则

适合另开小窗口的情况：

- 一个概念需要系统课程，但不影响当前产品判断。
- Syc 想亲手修改一小段代码达到 L4。
- 想比较两个技术方案的历史、原理或行业经验。
- 想重复练习某个命令、调试动作或故障恢复。

主窗口保留当前任务的目标、进度和交接物；小窗口只学习一个最小主题。学习结果只有确实改变项目决策时，才通过 Brain CLI 写回主项目。

## 7. 持续记录

- `docs/GLOSSARY.md`：名词的人话解释、目标深度和当前已覆盖深度。
- `docs/LEARNING_LOG.md`：每个任务已经交付的过程讲解与可选深挖入口。
- `docs/TASK_TEMPLATE.md`：保证边做边讲的任务模板。
- Project Brain：只保存会改变未来开发行为的耐久决策，不保存学习流水或考试成绩。
